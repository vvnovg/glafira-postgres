# Смоук P3a «Видеть» — топ запросов, карточка, EXPLAIN, консоль

Сборка: `pnpm tauri dev`. Стенд: `docker compose -f dev/docker-compose.yml up -d --no-recreate pg-perf` и нагрузка
`docker exec -d gp-pg-perf pgbench -n -U postgres -d perf -f /perf/heavy.sql -c 4 -T 600` (dev/perf/README.md).
Подключения создаются кнопкой «+» над деревом (сервер `localhost`, порт `5471`, БД по умолчанию `perf`, окружение `dev`):
- `perf-diag` — роль `glafira_diag` / `glafira-secret` (`pg_monitor`, `pg_read_all_data`, прав записи в `shop` нет); шаги 1–6 и 10–14;
- `perf-app` — роль `glafira_app` / `app-secret` (права записи в `shop`, не `pg_monitor`), флажок «Только чтение» снят; шаги 7–9.

1. **Готовность.** Форма `perf-diag` → «Проверить»: пункты «pg_stat_statements.track_planning» — Включён, «Чтение таблиц приложения (EXPLAIN)» — Разрешено, расширения hypopg, pg_stat_kcache, pg_wait_sampling — установлены.
2. **Топ «с момента сброса».** Дерево → `perf-diag` → Диагностика → Запросы: таблица со строками pgbench, тексты появляются через секунду, сортировка по «Вызовов» ставит точечный выбор покупателя (`SELECT * FROM shop.customers WHERE id = $1`) наверх; в находках — «… всех вызовов по … мс» (подсказка «Похоже на N+1»), «Temp-файлы: … на вызов» и «Попадание в кэш …»; подвал — `pg_stat_statements 1.11`, время сброса статистики.
3. **Окно.** Режим «За 5 мин»: значок «Идёт первый тик сэмплера…», через минуту — «Накоплено 1 из 5 мин» и строки с дельтами; заголовки «Stddev» и «Max» неактивны (подсказка «Недоступно для этой версии или режима»). Закрыть вкладку, подождать три минуты (промежуток засчитывается после 2,5 минут), открыть снова — таблица продолжается с прежними данными, а в карточке запроса (шаг 4) на спарклайне виден разрыв и строка «Промежутков в истории: 1».
4. **Карточка.** Клик по строке «SELECT count(*) FROM shop.orders WHERE status = $1»: заголовок вкладки — начало текста, текст запроса с кнопкой «Копировать текст запроса», метрики в две колонки («С момента сброса» и «За 60 мин»), спарклайны растут по минутам, экземпляры (при работающем pgbench); блок «Ожидания» сначала с подсказкой (буфера активности ещё нет); открыть «Профиль ожиданий», через несколько секунд вернуться в карточку и нажать «Обновить» — появится таблица событий; «Таблицы появятся после первого плана» и ссылка «Получить план».
5. **План и ANALYZE чтения.** «Получить план» (или подвкладка «План» → «План»): GENERIC_PLAN включён; дерево с Seq Scan on shop.orders (под Gather — Parallel Seq Scan) и выделенным горячим узлом; в «Обзоре» появилась таблица shop.orders со ссылкой на вкладку таблицы. Снять GENERIC_PLAN, ввести в `$1` значение `disputed`, «План с выполнением» — факт, буферы, ярус «чтение», без подтверждения; в журнале действий записи нет.
6. **Права на запись.** Консоль EXPLAIN (из дерева) на `perf-diag`, база `perf`: `UPDATE shop.balances SET balance = balance + 1 WHERE customer_id = 1` → «План» → сообщение «Не хватает прав: EXPLAIN пишущей инструкции требует прав INSERT/UPDATE/DELETE на её таблицы даже без выполнения» (а не подсказка про `pg_read_all_data`); `SELECT balance FROM shop.balances WHERE customer_id = 1` → «План» строит дерево.
7. **Запись.** Консоль на `perf-app` (база `perf`), тот же `UPDATE`: «План с выполнением» → окно «Выполнить запрос и откатить» со списком `shop.balances` и предупреждением про триггеры, последовательности и блокировки → «Выполнить и откатить» → дерево с Update on shop.balances, в сводке «Ярус: запись»; журнал действий — строка «EXPLAIN ANALYZE (запись)» с объектом `shop.balances`, при раскрытии — база, срок и начало текста. `docker exec gp-pg-perf psql -U postgres -d perf -c "SELECT balance FROM shop.balances WHERE customer_id = 1"` — значение то же, что до шага.
8. **Защита.** Изменить `perf-app`: поставить «Только чтение» → для `UPDATE` «План с выполнением» даёт подсказку «Запись недоступна: подключение только для чтения», `SELECT` выполняется. Снять «Только чтение» и сменить окружение на `prod` (при выборе `prod` флажок ставится сам — снять и его): для `UPDATE` окно подтверждения просит ввести имя подключения (`perf-app`), пока оно не введено, «Выполнить и откатить» недоступна; «Отмена» закрывает окно, новой записи в журнале нет. Вернуть окружение `dev`.
9. **Побочный эффект.** Перед шагом: `docker exec gp-pg-perf psql -U postgres -d perf -c "SELECT count(*) FROM pg_largeobject_metadata"`. Консоль на `perf-app`: `SELECT lo_creat(-1)` → «План с выполнением» → сообщение «Запрос пишет данные (volatile-функция или триггер)…», подсказка «Запрос пишет данные в транзакции только для чтения.» и кнопка «Выполнить как запись» → окно подтверждения (таблиц в нём нет) → «Выполнить и откатить» → дерево Result, ярус «запись»; журнал действий — новая строка «EXPLAIN ANALYZE (запись)» (объект — база `perf`); тот же `count(*)` в psql не изменился (откат отменил создание объекта).
10. **Ошибки.** Консоль: `SELECT 1; SELECT 2` → «План» → «Введите ровно одну инструкцию»; `SELECT pg_sleep(10)` со сроком 5 с → «План с выполнением» → «План не получен за отведённое время; выполнение прервано, изменений нет»; `SELEC 1` → «Сервер отверг запрос: …» и «Ошибка в строке 1, позиция 1» с отмеченным символом.
11. **Вставка плана.** «Вставить план» ← вывод `docker exec gp-pg-perf psql -U postgres -d perf -c "EXPLAIN (FORMAT JSON) SELECT 1"` целиком (с `QUERY PLAN` и `+`) → «Разобрать» → дерево «Result», без обращения к серверу. Затем вывод `docker exec gp-pg-perf psql -U postgres -d perf -c "EXPLAIN (ANALYZE, TIMING OFF, FORMAT JSON) SELECT count(*) FROM shop.customers"` → дерево с фактическими строками и циклами, в колонке времени у узлов «—», выделены узлы с наибольшей стоимостью.
12. **Для LLM.** В карточке (шаг 4) «Скопировать для LLM» → в буфере markdown с разделами «Среда», «Запрос», «Статистика», «План», «Таблицы» и DDL `shop.orders`. В консоли с запросом `SELECT count(*) FROM shop.orders WHERE status = 'disputed'` та же кнопка даёт markdown без раздела «Статистика».
13. **pg-single.** Подключение к `localhost:5460`: инструмент «Запросы» показывает «Статистика запросов (pg_stat_statements): pg_stat_statements не установлен в этой базе (CREATE EXTENSION pg_stat_statements)», таблицы нет.
14. **Справка.** F1 на вкладке «Запросы» открывает главу «Запросы» (раздел «Топ запросов»), на карточке — раздел «Карточка запроса», в консоли — «Консоль EXPLAIN».
