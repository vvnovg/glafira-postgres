# Смоук P4a: MCP-шлюз (Qwen Code и Claude Code)

Проверяем, что LLM-ассистент получает через Glafira только диагностику подключений, открытых для него, с замаскированными
литералами, и ничего не может изменить в базах.

Как читать: у каждого шага есть **Сделать** (по порядку) и **Должно быть** (отметьте, что совпало). Вопросы ассистенту
выделены цитатой — их вводят в Qwen Code обычным текстом. Шаги идут по порядку: часть шагов опирается на предыдущие.

Если что-то не так — запишите номер шага и что увидели (лучше со снимком экрана). Пригодятся:
- журнал вызовов: «Настройки» → «LLM-ассистенты (MCP)» → «Журнал» → «Обновить» (кнопка «Показать файл» открывает его на диске);
- лог приложения: `~/Library/Logs/io.github.vvnovg.glafira.postgres/app.log`.

## Подготовка

**Приложение.** Нужна сборка, установленная в `/Applications`: ассистент запускает именно её (из `pnpm tauri dev` — нет).
Сборка: `pnpm tauri build`, затем `.app` из `src-tauri/target/release/bundle/macos/` скопировать в `/Applications`. Команда
заканчивается ошибкой без `TAURI_SIGNING_PRIVATE_KEY` — это про архив обновления, `.app` для смоука годен. Локальная сборка
подписана иначе, чем релизная, поэтому при первом подключении macOS может спросить доступ к паролю в связке ключей — ответьте
«Разрешать всегда».

**Клиенты.** Qwen Code (`npm install -g @qwen-code/qwen-code`, вход в свою учётную запись) и Claude Code (`claude`).

**Стенд.** Поднять (никогда не `docker compose down`):

```bash
docker compose -f dev/docker-compose.yml up -d --no-recreate && scripts/wait-stand.sh
```

```bash
docker compose -f dev/docker-compose.yml up -d --no-recreate pg-perf && scripts/wait-perf.sh
```

**Подключения** (кнопка «+» над деревом, окружение `dev`, роль `glafira_diag`, пароль `glafira-secret`). Если подключение с
такими параметрами уже есть под другим именем, можно взять его — тогда в вопросах ассистенту называйте его имя.

| Имя | Куда | База |
|---|---|---|
| `lab` | `localhost:5470` | `orders` |
| `demo` | вид «Кластер Patroni», адрес REST API `http://localhost:8011`, пользователь API `patroni` / `patroni-secret`; подмена адресов — ниже | `orders` |
| `perf` | `localhost:5471` | `perf` |

Подмена адресов узлов у `demo` (участники Patroni сообщают внутренние имена, с компьютера они недоступны):

| Участник | Хост PostgreSQL | Порт PostgreSQL | Адрес API участника |
|---|---|---|---|
| `patroni1` | `localhost` | `5441` | `http://localhost:8011` |
| `patroni2` | `localhost` | `5442` | `http://localhost:8012` |
| `patroni3` | `localhost` | `5443` | `http://localhost:8013` |

«Проверить» в форме `demo` должно показать три узла без ошибок.

**Терминал.** Во всех командах ниже `$DATA` — каталог данных приложения. Задайте его в каждом новом окне терминала:

```bash
DATA="$HOME/Library/Application Support/io.github.vvnovg.glafira.postgres"
```

## Часть 1. Включение и уровни доступа

### Шаг 1. Включить MCP-сервер

**Сделать**
1. Откройте «Настройки» → «LLM-ассистенты (MCP)».
2. Если «Разрешить MCP-сервер» отмечен — снимите отметку и проверьте выключенное состояние.
3. Отметьте «Разрешить MCP-сервер».
4. В терминале:
   ```bash
   ls -l "$DATA/mcp.json" "$DATA/mcp.sock"
   ```
5. В блоке «Подключить клиент» нажмите любую кнопку «Копировать» и вставьте буфер в текстовый редактор.

**Должно быть**
- [ ] Выключено: «Сервер выключен», файла `mcp.json` нет.
- [ ] Включено: «Сервер работает», «Открыто для LLM: 0».
- [ ] `ls` показывает `-rw-------` у `mcp.json` и `srw-------` у `mcp.sock`.
- [ ] В «Подключить клиент» шесть фрагментов, в каждом путь `/Applications/Glafira for PostgreSQL.app/Contents/MacOS/glafira-pg`.
- [ ] В редакторе — тот фрагмент, который копировали.

### Шаг 2. Открыть подключения ассистенту

**Сделать**
1. Раскройте `lab` в дереве, затем откройте его форму: меню подключения → «Изменить подключение».
2. Группа «Доступ для LLM»: посмотрите, что выбрано. Выберите «Диагностика» → «Сохранить».
3. То же для `demo` и `perf`.

**Должно быть**
- [ ] До изменения выбрано «Нет».
- [ ] После сохранения у `lab` в дереве значок «LLM», раскрытый `lab` не свернулся (подключение не переоткрывалось).
- [ ] В «Настройках» → «LLM-ассистенты (MCP)»: «Открыто для LLM: 3».

**Экспорт и импорт не переносят уровень доступа**

**Сделать**
1. Создайте временное подключение `tmp-llm` (параметры как у `lab`), «Доступ для LLM» → «Диагностика» → «Сохранить».
2. Кнопка «Ещё действия» над деревом → «Экспортировать всё…» → сохраните, например, в `~/Desktop/glafira-export.json`.
3. В терминале:
   ```bash
   grep -c llmAccess ~/Desktop/glafira-export.json
   ```
4. Удалите `tmp-llm`.
5. «Ещё действия» → «Импортировать…» → тот же файл → «Импортировать».
6. Удалите вернувшийся `tmp-llm`.

**Должно быть**
- [ ] `grep` печатает `0`.
- [ ] В окне импорта `tmp-llm` в группе «Новые».
- [ ] У импортированного `tmp-llm` значка «LLM» нет. У `lab`, `demo`, `perf` значки остались.

## Часть 2. Qwen Code

### Шаг 3. Qwen Code сам запускает Glafira

**Сделать**
1. В «Подключить клиент» скопируйте фрагмент «Qwen Code: команда» и выполните его в терминале (сервер добавится для всех каталогов).
2. Закройте Glafira (⌘Q) и проверьте файлы:
   ```bash
   ls "$DATA" | grep mcp
   ```
3. Запустите Qwen Code в пустом каталоге:
   ```bash
   mkdir -p ~/smoke-p4a && cd ~/smoke-p4a && qwen --allowed-mcp-server-names glafira-pg
   ```
   Флаг оставляет Qwen Code только сервер Glafira, если у вас настроены и другие MCP-серверы. Дальше `qwen` в этом
   сценарии запускайте так же.
4. Glafira откроется с диалогом. **Не нажимая ничего в диалоге**, спросите в Qwen Code:
   > Какие подключения ты видишь в Glafira?
5. В диалоге нажмите «Разрешить».
6. В Qwen Code введите `/mcp`.

**Должно быть**
- [ ] После ⌘Q в списке только `mcp-audit.jsonl`: `mcp.json` и `mcp.sock` удалены.
- [ ] Glafira открылась сама, не дольше чем за 25 секунд.
- [ ] Поверх окна — диалог «<клиент> хочет подключиться к Glafira», в тексте «…открытых для LLM-ассистентов: 3». Имя —
      как сообщает клиент: Qwen Code 0.26 называет себя `qwen-cli-mcp-client-glafira-pg` (версия 0.0.1); ниже оно сокращено
      до «клиент Qwen».
- [ ] Фокус на окне диалога, кнопка «Разрешить» не выделена.
- [ ] Вопрос, заданный до ответа в диалоге, получил ошибку `client_not_approved`.
- [ ] После «Разрешить» клиент Qwen есть в «Подтверждённых клиентах», внизу боковой панели — «LLM: <имя клиента Qwen>».
- [ ] `/mcp` показывает сервер glafira-pg и 14 инструментов.

**Сделать**

3. Спросите:

4. Повторите команду из пункта 2.

**Должно быть**

- [ ] Индекс: `hypothetical_index`; в ответе стоимость «было / стало» и используется ли индекс.
- [ ] Число индексов до и после одинаковое (реальный индекс не создан).

### Шаг 10. Опасный SQL не проходит

**Сделать** — задайте одним сообщением (локальной модели так быстрее):
> Сделай explain_query на perf по очереди для каждого запроса и покажи, что вернул каждый вызов: 1) `SELECT pg_sleep(30)`
> 2) `SELECT pg_stat_reset()` 3) `SELECT * FROM ts_stat('SELECT 1')` 4) `SELECT 1; SELECT 2` 5) `DELETE FROM shop.audit`
> 6) `SELECT count(*) FROM shop.orders WHERE status = 'new'`

До и после посчитайте строки `shop.audit`:
```bash
docker exec gp-pg-perf psql -U postgres -d perf -c "SELECT count(*) FROM shop.audit"
```

**Должно быть**
- [ ] `pg_sleep`, `pg_stat_reset`, `ts_stat` — ошибка `forbidden_function`.
- [ ] `SELECT 1; SELECT 2` — ошибка `invalid_sql`.
- [ ] `DELETE` у роли `glafira_diag` — ошибка `NOT_AUTHORIZED` («EXPLAIN of a write statement needs INSERT/UPDATE/DELETE
      privileges…»): PostgreSQL требует права на запись даже для плана. У роли с правом `DELETE` (например, `glafira_app`) —
      план со строкой `Delete on shop.audit`. Число строк до и после одинаковое в обоих случаях.
- [ ] `SELECT … status = 'new'` — план. Литерал `'new'` в плане остаётся: SQL прислала сама модель, такой план не
      маскируется (маскируется план по `queryId`, §6.1); в журнале поле `sql` пишется целиком.

3. Найдите в журнале `explain_query` по `queryId` (шаг 9) и наведите на его кнопку.

**Должно быть**
- [ ] Открылась вкладка «EXPLAIN — perf» с тем же SQL, базой `perf` и узлом; план сам не строится.
- [ ] У вызова по `queryId` кнопка неактивна, подсказка «Недоступно: вызов задан queryId, текста запроса в журнале нет».

## Часть 4. Политика, второй экземпляр, справка

### Шаг 16. Политика организации

Нужны права администратора (`sudo`). После каждой смены файла политики перезапускайте Glafira (⌘Q и открыть снова).

**Сделать — вариант 1: MCP запрещён**
```bash
rm -f /tmp/policy.plist && plutil -create xml1 /tmp/policy.plist
plutil -insert mcpEnabled -bool NO /tmp/policy.plist
sudo mkdir -p "/Library/Managed Preferences"
sudo cp /tmp/policy.plist "/Library/Managed Preferences/io.github.vvnovg.glafira.postgres.plist"
sudo chmod 644 "/Library/Managed Preferences/io.github.vvnovg.glafira.postgres.plist"
```
Перезапустите Glafira, затем запустите `qwen`.

**Должно быть**
- [ ] Выключатель «Разрешить MCP-сервер» неактивен, рядом «Отключено вашей организацией».
- [ ] В дереве значков «LLM» нет; в форме подключения — «MCP отключён вашей организацией: уровень не действует».
- [ ] Qwen Code показывает «MCP is disabled by your organization».

**Сделать — вариант 2: только диагностика**
```bash
rm -f /tmp/policy.plist && plutil -create xml1 /tmp/policy.plist
plutil -insert mcpMaxAccess -string diagnostics /tmp/policy.plist
sudo cp /tmp/policy.plist "/Library/Managed Preferences/io.github.vvnovg.glafira.postgres.plist"
```
Перезапустите Glafira и задайте ассистенту любой вопрос о `lab`.

**Должно быть**
- [ ] В разделе MCP — «Доступ к данным ограничен вашей организацией».
- [ ] Уровень «Диагностика» работает: ассистент отвечает.

**Сделать — вариант 3: ошибочное значение**
```bash
rm -f /tmp/policy.plist && plutil -create xml1 /tmp/policy.plist
plutil -insert mcpMaxAccess -string everything /tmp/policy.plist
sudo cp /tmp/policy.plist "/Library/Managed Preferences/io.github.vvnovg.glafira.postgres.plist"
```
Перезапустите Glafira.

**Должно быть**
- [ ] MCP запрещён (как в варианте 1).
- [ ] В «О программе» — строка «Политика организации: …» с ошибкой.

**Убрать политику** и перезапустить Glafira:
```bash
sudo rm "/Library/Managed Preferences/io.github.vvnovg.glafira.postgres.plist"
```

4. Во втором окне откройте «Настройки» → «LLM-ассистенты (MCP)».
5. Повторите команду из пункта 2. Закройте второе окно (⌘Q в нём).

**Должно быть**
- [ ] Во втором окне — «Сервер работает в другом окне Glafira».
- [ ] `pid` в `mcp.json` не изменился.

### Шаг 18. Справка и переход к разделу

**Сделать и проверить**
- [ ] F1 при фокусе в разделе MCP открывает главу «LLM-ассистенты (MCP)».
- [ ] F1 при фокусе на выборе языка открывает «Начало работы».
- [ ] Щелчок по индикатору «LLM: …» внизу панели открывает «Настройки», прокрученные к разделу MCP.
