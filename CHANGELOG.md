## 0.3.0
Release date: 2026-10-25.
- On-call diagnostics: a “Diagnostics” group in the connection tree; every tool has its own tab with a node selector (“Follow the leader” by default), a refresh interval (2, 5, 10 or 30 seconds, or paused) and a findings block. Tools: pulse of the cluster nodes, sessions, idle in transaction, wait profile, locks and queued DDL, xmin horizon, replicas, replication slots and subscriptions; for a Patroni cluster, failover readiness and the health matrix. Every tool name has a “?” hint. Health matrix cells are colored by the member's role: an expected 503 (for example, `/primary` on a replica) is gray, a replica out of the load balancer pool is yellow, red means a real problem only. The tools themselves only read: `SELECT` on PostgreSQL nodes and `GET` to the Patroni REST API.
- Findings: severity (info, warning, critical), a title with numbers, a “what to do” hint, a ready-made command to copy (the app does not run it) and a jump to the right tool on the right node; thresholds are the same for all environments.
- Activity sampler and wait profile: one light query to `pg_stat_activity` per second per node while the tab is open; up to 60 minutes of history in memory (at most 500,000 rows), windows of 5, 15 and 60 minutes, a chart of average active sessions by wait class, top waits and queries, breakdowns by application, role, database and client. The sampler has its own connection per node.
- Scheduled Patroni switchovers and restarts are shown in the cluster overview: a banner and a mark in the member's row.
- PostgreSQL 13–18: the queries of every tool run on the version matrix of the stand; what the server version or the role's rights (`pg_monitor`) do not provide is listed under the findings block.
- Guide: the “Diagnostics” chapter (F1 on a tool tab opens its section); the administrator guide has a “Diagnostics” section (rights, load, Patroni REST API).
- Development stand: the `pg-lab` service (logical slots, a subscription, prepared transactions) and the `glafira_app` application role for scenarios; integration tests `it_diag` and `it_sampler`.
- On-call actions on sessions: cancelling a query and terminating a session from the session panel, terminating the root blocker in the lock tree, and terminating idle in transaction sessions older than N minutes as a batch (up to 500 sessions per action). The preview reads the sessions again and shows what can be done and what cannot, and why (the `pg_signal_backend` rights, a superuser session, the app's own connection); a session is addressed by its PID and start time, and a batch checks the condition again, so a session that woke up is not terminated. Only a running query can be cancelled: a session waiting for a client command ignores a cancel, so the button is inactive, and terminating the session ends a hanging transaction. The “idle in transaction” and “root blocker” findings got buttons for the same actions.
- Dropping a replication slot: inactive slots only, with the slot name typed in; for a Patroni cluster, a warning that Patroni will recreate the slot (a member slot or a permanent slot). Needs the `REPLICATION` attribute or a superuser; the readiness checklist item “Dropping replication slots” tells how to grant it.
- Patroni actions in the cluster overview: switchover (now or scheduled, a candidate or “Let Patroni choose”, candidate readiness, the number of leader sessions that will break), failover (only when there is no running leader, with the candidate's name typed in), restart (now or scheduled, “Only if a restart is pending”), cancelling a scheduled switchover or restart, pause and resume. Needs the Patroni API login in the profile. Before sending, the app checks once more that the leader is the one the preview showed and that the candidate is a ready replica. The request goes to the members that answered the last poll (the leader first), and to the next address only if the connection failed; a restart and its cancellation go to the member's own API. If Patroni does not answer after the request was sent, the request is not repeated, and the watch shows the outcome. A scheduled time defaults to 15 minutes from now; a time in the past is not accepted.
- Action safeguards: a read-only connection has no action buttons, and the app refuses a direct call too; on prod, the connection name must be typed in, for a batch also the number of sessions, for a failover the candidate's name. The checks run in the app before it talks to the server. An action uses a separate connection that is not read-only.
- Watching after Patroni actions: the “Progress” panel shows the steps up to “Done” (the old leader stepped down, the new leader is running, the timeline increased, replicas are streaming; restarted; the cluster state changed), and the topology is polled every 2 seconds; the deadlines are 2 minutes for switchover and failover, 5 minutes for restart, 30 seconds for pause. Closing the panel stops the watching.
- Actions journal: the `actions.jsonl` file in the data directory (permissions 0600, rotated into `actions.1.jsonl` at 5 MB) and the “Actions journal” tab in the “Diagnostics” group. A record holds the connection, the node, the outcome, for every session its data, result and query text (the first 500 characters, literals included), for Patroni the request without credentials and the response. Safeguard refusals are not recorded; if writing failed, the action window says “The journal was not written”.
- Guide: the “Actions”, “Patroni actions” and “Actions journal” sections in the “Diagnostics” chapter; the administrator guide has an “Actions” subsection (rights, advice on a separate role for actions with `REPLICATION`, the Patroni API account, the action connection, `actions.jsonl`).
- Stand and tests: integration tests `it_actions` and `it_patroni_actions`; the Patroni scenarios that change the cluster run under `GPG_IT_DOCKER=1` and restore the stand themselves, failover also needs `GPG_IT_FAILOVER=1`.
- Update notes in About → Updates are shown in the interface language (in English if there is no translation) and as formatted text instead of raw Markdown. This applies to updates offered to version 0.3.0 and later; earlier versions show the notes as plain English text.
- The changelog is now in English (`CHANGELOG.md`); its Russian version is in `docs/changelog/ru.md`.

## 0.2.0
Release date: 2026-10-24.
- SSH tunnel through the system OpenSSH: a server, a host list and a Patroni cluster connect through a bastion. Login with the SSH agent, a key file (including one with a passphrase) or a password; the password and the passphrase are kept in the system secret store. One `ssh -D` process per connection: the bastion resolves node names and Patroni REST API addresses. A password or a passphrase needs OpenSSH 8.4+; the agent and a key without a passphrase work with any version.
- Host key trust dialog: on the first login, confirmation by fingerprint (`ssh` itself writes the key to `~/.ssh/known_hosts`); the app does not accept a changed key.
- The tunnel looks after itself: after a drop it restarts with pauses of 1, 2, 5, 10 and 30 seconds; after a refused login the retries stop until “Reconnect”. An “SSH” step in the connection check; the `ssh-<id>.log` logs go into the diagnostics archive.
- Object tabs — table, view, materialized view, function, sequence: columns, indexes, constraints, incoming foreign keys, size and statistics, partitioning, triggers, the function definition, sequence bounds and usage. They open from the tree, have a “Refresh” button and re-read the data after the connection comes back.
- Table DDL from the catalog with a “Copy DDL” button (not a replacement for `pg_dump`: no grants, RLS policies or owners). Foreign keys and not-validated constraints are emitted as separate `ALTER TABLE … ADD CONSTRAINT` statements.
- PostgreSQL 13–18 support: catalog and tab queries run on the version matrix of the stand and in CI. The app's sessions set `search_path = pg_catalog` and `DateStyle = ISO`, so that definitions always contain schema names.
- Display change: types outside `pg_catalog` in function signatures (tree, function tab) and in column types are now shown with the schema — `public.my_type` instead of `my_type`.
- Guide: the “Connections” and “Tree and objects” chapters (the “Help” tab; F1 opens the chapter of the current screen); the administrator guide has an “OpenSSH” section and networking through a bastion.
- Connection import: SSH settings are part of the connection settings whose change removes saved passwords.
- Limitation: there is no protection against a second app instance — a second launch ends the first one's `ssh` processes at startup.
- Development stand: the `bastion` SSH bastion (keys are created by `dev/ssh/gen-keys.sh`) and the `matrix` profile with PostgreSQL 13–18 servers.

## 0.1.0
Release date: 2026-10-22.
- The first release of Glafira for PostgreSQL: diagnostics of PostgreSQL and Patroni clusters.
- Three kinds of connections: a server, a host list (the primary is found automatically, like multi-host JDBC), a Patroni cluster (REST API). Pasting a connection string (JDBC, `postgresql://…`, `host=… port=…`); passwords in the system secret store, otherwise `~/.pgpass`.
- Step-by-step connection check and a diagnostics readiness checklist: the `glafira_diag` role, `pg_stat_statements`, server parameters.
- Cluster overview: members with roles, lag and timeline, polling every 10 s, an event log (leader change, unreachable nodes, pause).
- Tree: folders → connections → nodes / databases → schemas → tables, views, materialized views, functions, sequences; partitions, roles, extensions.
- Connection folders, export and import of connections without passwords, duplicating a connection.
- English and Russian interface, “?” hints, a built-in guide: the “Help” tab, F1, the Help menu on macOS.
- Administrator policy (`updatesEnabled`, `updateUrl`, `language`): an MDM profile on macOS, the registry on Windows, `/etc` on Linux.
- Automatic updates: a check at startup and in About → “Check for updates”; an organization can turn updates off or point to a mirror.
- About: version, build, policy, diagnostics archive (version, logs, profiles without passwords).
- The source code is open under the Apache License 2.0, all features are free. “Support the project” is at the bottom of the left panel, in About and in the Help menu (macOS).
- Installers: macOS (`.dmg` signed with Developer ID and notarized; `.pkg` for distribution via MDM), Windows (`.msi`), Linux (`.deb`, `.rpm`, `.AppImage`).
