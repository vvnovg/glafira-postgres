# LLM-ассистенты (MCP)

Glafira может работать шлюзом для LLM-ассистента: Qwen Code, Claude Code, Claude Desktop, Cursor или другого клиента с поддержкой MCP (Model Context Protocol). Ассистент читает диагностику подключений, которые вы ему открыли, — топологию, отчёты инструментов с находками, активность, топ запросов, карточки запросов, таблицы, параметры сервера, планы без выполнения — и проверяет гипотезы индексов через hypopg. Медленный запрос из консоли EXPLAIN или карточки запроса можно передать ему на оптимизацию: переписанный запрос и индексы возвращаются в панель, где вы сравниваете планы (см. [Запрос на оптимизацию и предложения](llm-mcp.md#optimization)). На тестовых стендах ему можно разрешить и чтение данных через `SELECT` (см. [Уровень «Диагностика и данные»](llm-mcp.md#data-level)). Изменить базу через Glafira он не может: отмену и завершение сессий, удаление слотов, switchover и перезапуск, создание индексов и правку запросов вы делаете сами, а ассистент подсказывает, что и где сделать.

## Как это устроено {#how-it-works}

Клиент запускает `glafira-pg mcp` — тот же файл приложения в режиме без окна. Команда находит запущенную Glafira по файлу `mcp.json` в папке данных, соединяется с ней через локальный сокет (на Windows — именованный канал) и передаёт ей запросы ассистента. Glafira отвечает через свои подключения: пароли, ключи SSH и строки подключения остаются в ней, ассистент их не получает.

Сокет доступен только вашему пользователю. Для входа нужен токен, который Glafira записывает в `mcp.json` при каждом запуске сервера; файл доступен только владельцу и существует, пока сервер работает.

## Включение {#enable}

1. Откройте [[ui:sidebar.settings]], раздел [[ui:settings.mcp.section]].
2. Отметьте [[ui:settings.mcp.enable]]. Статус сменится на [[ui:settings.mcp.state.running]].
3. Откройте форму подключения ([[ui:sidebar.editConnection]] в меню подключения), выберите [[ui:connections.form.llmLevels.diagnostics]] в группе [[ui:connections.form.llmAccess]] и сохраните. В дереве у подключения появится значок `LLM`. Третий уровень, [[ui:connections.form.llmLevels.data]], — для тестовых стендов: см. [Уровень «Диагностика и данные»](llm-mcp.md#data-level).

По умолчанию MCP выключен, а у каждого подключения уровень [[ui:connections.form.llmLevels.off]]: такие подключения ассистент не видит. Уровень не переносится при экспорте и импорте подключений: импортированное подключение закрыто для ассистента, пока вы не откроете его сами. Смена уровня не переоткрывает соединение. Флажок [[ui:common.readOnly]] на доступ ассистента не влияет: ассистент ничего не меняет. Окружение `prod` тоже ничего не запрещает; на уровне [[ui:connections.form.llmLevels.data]] форма только предупреждает: [[ui:connections.form.llmProdWarning]].

Если MCP уже обслуживает другое окно Glafira, статус — [[ui:settings.mcp.state.otherInstance]]; клиенты подключаются к тому окну.

## Подключение клиента {#connect-client}

В блоке [[ui:settings.mcp.connect.title]] — готовые фрагменты с путём к установленному приложению и кнопками копирования:

- Qwen Code — команда `qwen mcp add glafira-pg "<путь>" mcp` или блок `mcpServers` для файла `~/.qwen/settings.json`;
- Claude Code — команда `claude mcp add glafira-pg -- "<путь>" mcp`;
- Claude Desktop — блок для файла `claude_desktop_config.json`; после правки перезапустите Claude Desktop;
- Cursor — блок для файла `~/.cursor/mcp.json`;
- любой другой клиент, который запускает MCP-сервер командой (stdio), — команда и аргумент `mcp`.

Клиент может работать и с моделью на вашем компьютере, без облака, — об этом глава [Локальные модели](local-llm.md).

Сначала откройте Glafira, потом запускайте клиент. Если Glafira закрыта, команда `glafira-pg mcp` запустит её сама и подождёт до 25 секунд, но клиенты ждут ответа сервера недолго (Qwen Code — 30 секунд), и при медленном запуске подключение может не успеть. Если вы переустановили Glafira в другое место, скопируйте фрагмент заново.

Где клиент хранит сервер, зависит от его области (scope). Claude Code по умолчанию добавляет сервер в область `local` — только для текущего проекта; чтобы glafira-pg был доступен во всех проектах, добавьте `--scope user` (`-s user`) перед именем: `claude mcp add --scope user glafira-pg -- "<путь>" mcp`. Qwen Code по умолчанию использует область `user` (всем проектам); `-s project` ограничивает сервер текущим проектом. Остальные флаги — в `claude mcp add --help` и `qwen mcp add --help`.

## Подтверждение клиента {#approve}

Когда клиент подключается впервые, Glafira поверх любого экрана показывает диалог: имя и версия клиента и сколько подключений открыто для LLM-ассистентов. Нажмите [[ui:mcp.approval.allow]] или [[ui:mcp.approval.reject]]; Escape — тоже отказ. Пока вы не ответили, ассистент получает ошибку `client_not_approved` и просит ответить в окне Glafira. Если ждут несколько клиентов, диалоги идут по очереди.

Разрешённый клиент запоминается по имени и появляется в списке [[ui:settings.mcp.clients.title]]. Отказ не запоминается: при следующем подключении Glafira спросит снова. Клиент без имени показывается как [[ui:mcp.unknownClient]], и разрешение действует только до конца его сессии.

Имя клиента может подделать любая программа на вашем компьютере: подтверждение показывает, кто подключился, а защищает токен в файле `mcp.json`, доступном только вашему пользователю.

## Что видит ассистент {#access}

С уровнем [[ui:connections.form.llmLevels.diagnostics]] ассистент получает:

- открытые подключения (имя, окружение, вид, папка, уровень, база по умолчанию) и их топологию: узлы с ролями, лагом и таймлайном, состояние Patroni, события топологии;
- сводку здоровья: пульс и находки быстрых инструментов (сессии, блокировки, горизонт xmin, реплики, слоты, у Patroni — готовность к failover и health);
- отчёт любого инструмента группы [[ui:sidebar.diagnostics]] с находками и текстами «что сделать»;
- активность: сессии с фильтрами и наблюдение за ними до 50 секунд — ожидания, главные запросы, появившиеся и ушедшие сессии;
- топ запросов `pg_stat_statements` — с момента сброса, за окно (если вкладка [[ui:diag.tools.queries]] уже копила историю) или наблюдением до 50 секунд — и карточку запроса;
- таблицу: колонки, индексы, ограничения, статистику, DDL и статистику колонок `pg_stats` без значений;
- параметры сервера из `pg_settings`: пароли в строках подключения (в том числе в виде URI) и в командах (`primary_conninfo`, `archive_command` и других) заменены на `***`, `ssl_passphrase_command` и параметры с «секретными» именами (в том числе у расширений) скрыты целиком; строки с источником `client` и `session` — это настройки собственного соединения Glafira, а не сервера;
- план запроса без выполнения (EXPLAIN без ANALYZE) с рекомендациями и проверку гипотезы индекса через hypopg — до пяти индексов за раз; без расширения hypopg ассистент получит подсказку, как его включить.

На уровне [[ui:connections.form.llmLevels.data]] ассистент получает всё это без маскирования, а кроме того значения из `pg_stats` и чтение данных инструментом `run_select`: см. [Уровень «Диагностика и данные»](llm-mcp.md#data-level).

SQL ассистента проверяется до отправки на сервер: принимается ровно одна инструкция `SELECT`, `INSERT`, `UPDATE`, `DELETE` или `MERGE` (без ANALYZE она не выполняется), а служебные команды и опасные функции (`pg_sleep`, `dblink`, `lo_import`, `set_config`, сигналы, сбросы статистики `pg_stat_reset*`, `ts_stat`, `ts_rewrite`, файловые функции и другие) отвергаются. План строится в транзакции только для чтения, которая всегда откатывается, на отдельном соединении с `application_name = glafira-pg-mcp`; сессия MCP к тому же начинается с `default_transaction_read_only = on`. Ошибки позиции в SQL указывают на исходный текст ассистента. У инструмента `run_select` правила строже — они описаны в разделе [Уровень «Диагностика и данные»](llm-mcp.md#data-level).

Размер ответов ограничен: ответ — до 100 КБ, в карточке запроса — не больше 20 выполняющихся экземпляров (с общим числом), в карточке таблицы — не больше 200 секций (с общим числом), текст запроса сессии — до 2 КБ. Ошибки SSH-туннеля ассистенту показываются общим текстом, без адреса бастиона, а ошибки узлов в отчётах — без подробностей и путей.

Ассистент никогда не получает пароли и секреты хранилища, настройки SSH, строки подключения профилей, журнал действий, журнал MCP и настройки приложения. Метрик ОС и логов сервера в Glafira нет — их ассистент попросит у вас.

Тексты запросов, комментарии и имена объектов приходят из базы и могут быть заданы кем угодно. Glafira предупреждает ассистента, что это данные, а не инструкции.

## Маскирование {#masking}

На уровне [[ui:connections.form.llmLevels.diagnostics]] Glafira заменяет литералы в текстах запросов на `$1`, `$2`… до того, как отдать их ассистенту: строки, числа, `E'…'`, строки в долларовых кавычках и другие. Тело комментария заменяется на `/*…*/` (в комментариях бывают данные, например теги sqlcommenter); метка `/* glafira */` остаётся. Маскируются тексты `pg_stat_activity` во всех инструментах, тексты `pg_stat_statements`, выполняющиеся экземпляры в карточке запроса и условия в узлах плана (`Filter`, `Index Cond` и другие) у планов, построенных не по SQL ассистента. Сколько литералов замаскировано, видно в журнале.

Не маскируются SQL, который прислал сам ассистент, и его план, DDL таблиц (значения по умолчанию и `CHECK` — это схема), имена объектов, ролей и приложений, а также снимок запроса на оптимизацию — его отправляете вы сами (на любом уровне, см. [Запрос на оптимизацию и предложения](llm-mcp.md#optimization)). Данные, вписанные в имена, маскирование не распознаёт. Текст, обрезанный сервером посередине литерала, маскируется до конца.

Маскирование не зависит от настройки `standard_conforming_strings` узла: текст маскируется при обоих её значениях, и если границы литералов получаются разными, ассистент получает только общее начало и одну метку `$N…` вместо остатка. Поиск по тексту (параметр `search` у `get_top_queries` и в списке запросов) на уровне [[ui:connections.form.llmLevels.diagnostics]] ищет по замаскированному тексту среди первых 200 строк топа, поэтому значения литералов найти нельзя.

На уровне [[ui:connections.form.llmLevels.data]] Glafira ничего не маскирует ни в одном инструменте.

## Сессии, отзыв и журнал {#sessions-log}

Пока клиент подключён, внизу боковой панели виден индикатор `LLM` с именем клиента (или числом клиентов); во время вызова он подсвечивается. Щелчок открывает раздел MCP в настройках.

- [[ui:settings.mcp.sessions.title]] — клиент, начало и число вызовов; [[ui:settings.mcp.sessions.disconnect]] закрывает одну сессию, [[ui:settings.mcp.sessions.disconnectAll]] — все.
- [[ui:settings.mcp.clients.title]] — [[ui:settings.mcp.clients.revoke]] забывает клиента и закрывает его сессии; при следующем подключении он снова попросит подтверждение.
- Новый уровень в форме подключения, отзыв клиента и выключение MCP действуют со следующего вызова ассистента; переподключать клиент не нужно.
- [[ui:settings.mcp.audit.title]] — последние 200 записей: время, клиент, инструмент или событие, подключение, итог, длительность, число замаскированных литералов (у `run_select` — число строк). Аргументы длиннее 1 КБ обрезаются, SQL записывается целиком до 16 КБ, ответы и значения, прочитанные `run_select`, не записываются. События [[ui:settings.mcp.audit.events.requestCreated]] и [[ui:settings.mcp.audit.events.proposalAnswered]] приходят от [запросов на оптимизацию](llm-mcp.md#optimization). [[ui:settings.mcp.audit.reveal]] открывает файл `mcp-audit.jsonl`.
- У успешного вызова `explain_query` или `run_select` кнопка [[ui:settings.mcp.audit.openInConsole]] открывает [консоль EXPLAIN](queries.md#console) подключения с тем же SQL, базой и узлом (если вызов пришёл без базы — с базой подключения по умолчанию). Ничего не запускается: постройте план сами и сравните с тем, что видел ассистент. Кнопка недоступна, если аргументы в журнале обрезаны, вызов задан `queryId`, подключения больше нет или доступ для LLM у него выключен; причина — в подсказке кнопки.

Чтобы выключить MCP совсем, снимите флажок [[ui:settings.mcp.enable]]: клиенты отключатся, файл `mcp.json` удалится.

## Политика организации {#policy}

Администратор может запретить MCP ключом политики `mcpEnabled`: флажок [[ui:settings.mcp.enable]] недоступен с пометкой [[ui:settings.mcp.policy]], сервер не запускается, а команда `glafira-pg mcp` завершается с ошибкой. Ключ `mcpMaxAccess` ограничивает уровень доступа сверху; при потолке `diagnostics` в разделе MCP написано [[ui:settings.mcp.dataPolicy]], подключения с уровнем [[ui:connections.form.llmLevels.data]] работают как [[ui:connections.form.llmLevels.diagnostics]] (тексты снова маскируются, `pg_stats` — без значений), в их форме написано [[ui:connections.form.llmDataAsDiagnostics]], а `run_select` отвечает `data_disabled`. Если политика не читается или у этих ключей неверное значение, MCP тоже запрещён, а ошибка видна в окне [[ui:sidebar.about]]. Подробности — в руководстве администратора.

## Запрос на оптимизацию и предложения {#optimization}

В консоли EXPLAIN (режим [[ui:diag.explain.sourceSql]], рядом с кнопками плана) и в карточке запроса (под текстом запроса) есть кнопка [[ui:llmAssist.ask.button]]. Она сохраняет снимок запроса для LLM-ассистента: узел, базу, текст, значения параметров последнего плана, статистику `pg_stat_statements` (в карточке), план в виде текста и DDL таблиц — то же содержимое, что даёт [[ui:diag.query.copyLlm]] (см. [Карточка запроса](queries.md#card)). Если для текущих текста, узла и базы плана ещё нет, Glafira пробует построить его без выполнения. Кнопка копирует строку для чата ассистента на языке интерфейса, например «Оптимизируй запрос r3a9f1c из Glafira (или /optimize_query r3a9f1c)»: вставьте её в Qwen Code, Claude Code или другой подключённый клиент. Снимок модель забирает инструментом `get_optimization_request`.

Снимок уходит модели как есть, без маскирования литералов, даже если подключение открыто только для диагностики: его отправляете вы сами, а в плане могут быть значения из формы параметров. Кнопка недоступна, пока MCP-сервер выключен или работает в другом окне Glafira, политика запрещает MCP или подключение закрыто для LLM-ассистентов; значок «?» рядом объясняет причину и где это включить. В карточке кнопка появляется, когда текст запроса известен и не обрезан; запрос длиннее 64 КБ передать нельзя.

Пока модель работает, консоль и карточка показывают «Ждёт ответа LLM: запрос r3a9f1c» и кнопку [[ui:llmAssist.ask.cancel]]: отменённый запрос модели больше не отдаётся, она получает `request_closed`. Новый запрос из той же консоли или из карточки того же запроса можно отправить, когда прежний получил ответ или отменён. Glafira хранит последние 50 запросов. Большой снимок урезается, чтобы уложиться в ответ 100 КБ: первыми уходят DDL последних таблиц и конец текста плана, а модель получает пометку, что опущено, и может прочитать это через `get_table_details` и `explain_query`.

Модель отвечает инструментом `propose_query_rewrite`: переписанный запрос, до пяти `CREATE INDEX`, обоснование (до 4 КБ) и ожидаемый эффект (до 1 КБ). Перед сохранением Glafira проверяет предложение: вид инструкции тот же, что у исходной; запрещённых функций нет; индексы проходят те же проверки, что у `hypothetical_index` (без `CONCURRENTLY` и `UNIQUE`, имя индекса отбрасывается); сервер может спланировать запрос (`prepare` и план без выполнения в транзакции `READ ONLY`, которая всегда откатывается, на узле запроса). Ошибку модель получает с текстом сервера и исправляет запрос сама. Переписанный запрос Glafira не выполняет и индексы не создаёт. Повтор того же предложения дубля не создаёт; на один запрос — не больше пяти предложений. Модель может предложить переписать запрос и по своей инициативе, без запроса из Glafira, например найдя его в топе: такое предложение появляется в консоли его подключения, когда в ней выбрана та же база.

Панель [[ui:llmAssist.panel.title]] под редактором консоли показывает предложения на запросы этой консоли и предложения без запроса для выбранной базы; пока предложений нет, она свёрнута. Новое предложение появляется сразу; если консоль на фоновой вкладке, у вкладки загорается точка. У выбранного предложения панель показывает исходный и предложенный текст рядом с подсветкой изменённых строк, обоснование и ожидаемый эффект как обычный текст (разметку модели панель не применяет), индексы, клиент и время. Под текстом — постоянная пометка: Glafira не проверяет, что переписанный запрос возвращает те же строки.

- [[ui:llmAssist.panel.compare]] строит оба плана без выполнения на узле предложения с теми же значениями параметров; предложенный запрос планируется вместе с его индексами через `hypopg` (виртуальные индексы живут только в сессии сравнения, см. [Рекомендации по плану](queries.md#recommendations)). Итог — стоимость «была / стала», горячие узлы обоих планов, рекомендации к обоим и используется ли каждый индекс. Если в базе нет `hypopg`, сравнение идёт без индексов, и это помечено. Запрос с `$1`, `$2`… без сохранённых значений сравнивается по общему плану, а для него нужен PostgreSQL 16 или новее; на более старых версиях сравните такой запрос в консоли со своими значениями. Сравнение идёт собственным соединением EXPLAIN Glafira, как в консоли. Итог сохраняется в предложении, и модель видит его в `list_proposals`.
- [[ui:llmAssist.panel.openInConsole]] подставляет предложенный текст в консоль вместе с базой и узлом предложения. Заменённый текст попадает в список [[ui:diag.explain.replaced.title]] под панелью (последние 10 текстов), откуда его возвращает кнопка; так же работает открытие запроса из журнала MCP. Дальше действуют обычные правила консоли, в том числе [план с выполнением](queries.md#analyze).
- [[ui:llmAssist.panel.accept]] и [[ui:llmAssist.panel.reject]] записывают ваше решение; к отклонению можно добавить причину до 500 символов — модель увидит её в `list_proposals`. Решение можно поменять позже. [[ui:llmAssist.panel.copy]] копирует предложенный текст. Применить изменение — поправить код приложения, создать индекс — предстоит вам самим.

В карточке запроса кнопка «Предложения LLM: N» в шапке считает предложения к этому запросу (по его `queryid` и по запросам, отправленным из карточки) и открывает консоль с исходным текстом и панелью, где выбрано самое свежее предложение (сначала — без ответа).

Предложения хранятся в `llm-proposals.json` в каталоге данных приложения (до 100, до пяти на запрос), запросы — в `llm-requests.json`; оба файла доступны только вашему пользователю. Журнал MCP записывает создание запроса и ваши ответы на предложения — без текста запроса и причины.

## Уровень «Диагностика и данные» и run_select {#data-level}

Третий уровень доступа для LLM в форме подключения, [[ui:connections.form.llmLevels.data]], рассчитан на стенды нагрузочного тестирования и тестовые базы. На нём модель видит всё, что и на уровне диагностики, но без маскирования ни в одном инструменте (тексты запросов, тексты сессий и планы — со значениями), получает частые значения и гистограммы колонок из `pg_stats` в `get_table_details` (значения длиннее 2 КБ обрезаются) и читает данные инструментом `run_select`. В дереве у такого подключения значок `LLM` заполнен. Если окружение подключения — `prod`, форма предупреждает, что данные production-базы будут уходить провайдеру LLM; это предупреждение, а не запрет. Если политика организации ограничивает доступ уровнем диагностики (`mcpMaxAccess`), подключение работает как [[ui:connections.form.llmLevels.diagnostics]], и форма об этом пишет.

`run_select` принимает ровно одну инструкцию `SELECT` (в том числе `VALUES`, `TABLE`, `WITH … SELECT`) без `INTO`, `FOR UPDATE` / `FOR SHARE` и изменяющих CTE на любой глубине и без параметров вида `$1`: значения пишутся прямо в текст запроса. База необязательна (по умолчанию — база подключения), узел тоже: без него запрос идёт на доступную реплику с наименьшим лагом, а если её нет — на лидера. Glafira проверяет запрос в несколько слоёв:

- дерево разбора `pg_query` и список запрещённых функций: административные, доступ к файлам, большие объекты, `dblink`, `http`, `set_config`, advisory-блокировки, `pg_sleep`, `pg_notify`, `query_to_xml` и родственные, функции расширений, которые выполняют SQL из строки (`pg_background`, `crosstab`, `connectby`, `xpath_table`, `pgr_*` из pgRouting), и все функции схем `net` (pg_net), `aws_s3` и `aws_lambda`, которые обращаются за пределы базы, — ошибка `forbidden_function`;
- отдельное соединение с `application_name = glafira-pg-mcp` и транзакция `BEGIN READ ONLY`, которая всегда откатывается, со `statement_timeout` 10 с и `lock_timeout` 1 с;
- сверка вызванных функций с `pg_proc` — сначала по именам в запросе, затем по пробному `EXPLAIN (VERBOSE)`, который показывает и функции, вызванные через представление или запись `t.f`: функция вне `pg_catalog`, не принадлежащая расширению, — пользовательская, её тело проверить нельзя, и `run_select` её отвергает (`user_function`); проба находит и запрещённые функции, не видные разбору. Функции расширений, например `pg_stat_statements` или PostGIS, разрешены, если их нет в списке.

Запрос выполняется курсором: по умолчанию 100 строк, не больше 500 (`maxRows`) и не больше 100 КБ ответа; значения обрезаются на сервере, и значение длиннее 2 КБ заканчивается пометкой `…[truncated]`; `truncated: true` в ответе значит, что строк было больше. На запрос отведено 10 секунд: когда они истекают, модель получает уже собранные строки, а если строк нет — `TIMEOUT`; открытие соединения в эти 10 секунд не входит, поэтому вызов может длиться чуть дольше. Если клиент отменяет вызов, Glafira останавливает запрос на сервере. В журнал MCP пишется текст запроса и число строк, значения — нет.

Проверки не делают роль подключения безопасной: функция расширения, оператор или приведение типа могут вызвать то, чего нет в списке, а `READ ONLY` не останавливает нетранзакционные действия, например сигналы другим сессиям. Поэтому у подключений с уровнем [[ui:connections.form.llmLevels.data]] в [чек-листе готовности](connections.md#readiness) есть пункт [[ui:readiness.llmRole.title]]: если роль подключения — суперпользователь или член `pg_signal_backend`, `pg_write_all_data`, `pg_read_server_files` или `pg_execute_server_program`, пункт предупреждает, что модель смогла бы сделать через `run_select`, если обойдёт список, и даёт SQL роли для стенда; то же предупреждение видно под уровнем в форме. Модель получает его полем `roleWarning` в `list_connections`, когда подключение проверено кнопкой [[ui:connections.form.test]] или выполнило `run_select` после запуска Glafira. Уровень предупреждение не выключает. Для стенда достаточно отдельной роли только для чтения:

```sql
CREATE ROLE glafira_llm LOGIN PASSWORD '…';
GRANT pg_monitor TO glafira_llm;         -- статистика для инструментов диагностики
GRANT pg_read_all_data TO glafira_llm;   -- PostgreSQL 14 и новее
-- В PostgreSQL 13 pg_read_all_data нет: в каждой базе, для каждой схемы, которую может читать модель
-- GRANT USAGE ON SCHEMA public TO glafira_llm;
-- GRANT SELECT ON ALL TABLES IN SCHEMA public TO glafira_llm;
```

Заведите с этой ролью отдельное подключение с уровнем [[ui:connections.form.llmLevels.data]], а основное оставьте на уровне [[ui:connections.form.llmLevels.diagnostics]].

## Сценарии (prompts) {#prompts}

Glafira даёт MCP-клиентам четыре готовых сценария (MCP prompts). Каждый клиент показывает их по-своему: Qwen Code и Claude Code — как слэш-команды (у Claude Code они называются `/mcp__glafira-pg__optimize_query` и так далее), другие клиенты — в своём списке подсказок, если вообще поддерживают MCP prompts; аргументы вводятся после команды или в форме — как принято в клиенте. Тексты сценариев — на английском, с просьбой отвечать на языке пользователя. `connectionId` — id подключения из `list_connections`; если вместо него указать имя подключения, первый вызов инструмента ответит `not_allowed` с советом вызвать `list_connections`, где ассистент может найти id. Id и имена узлов — одна строка до 128 символов, `symptom` — до 1000 символов, `windowS` — 300, 900 или 3600.

- `optimize_query` (аргумент `requestId`, необязательный: без него — последний ожидающий запрос): забирает запрос на оптимизацию, разбирает план и статистику, при необходимости проверяет гипотезы через `explain_query` и `hypothetical_index`, присылает одно или несколько предложений через `propose_query_rewrite` и коротко объясняет их в чате; дальше сравните планы в Glafira.
- `triage_incident` (`connectionId`, необязательный `symptom`): `get_health_summary`, затем `run_diagnostic` по находкам (блокировки, горизонт xmin, репликация, слоты, у Patroni — готовность к failover и health), при нагрузке — `observe_activity` на 30 с; итог — что происходит, вероятные причины, что сделать в Glafira (какой экран, какое действие) и что проверить вне её (логи сервера, ОС).
- `analyze_top_queries` (`connectionId`, необязательные `member` и `windowS`, по умолчанию 900): топ запросов за окно (без накопленной истории — `observe_top_queries` на 50 с или статистика с момента сброса), карточки и планы трёх–пяти главных запросов, рекомендации; кандидатов на переписывание модель присылает через `propose_query_rewrite`, и они появляются в панели консоли подключения.
- `review_config` (`connectionId`, необязательный `member`): изменённые и ключевые настройки (память, чекпойнты и WAL, autovacuum, таймауты, `track_io_timing`, `jit`, параллельность) с учётом числа соединений и нагрузки; рекомендации с рисками и пометкой, нужен ли перезапуск. Для Patroni модель предлагает правку через `patronictl edit-config`; Glafira конфигурацию не меняет.

Сценарии не обязательны: обычный вопрос в чате тоже работает, см. [Примеры вопросов](llm-mcp.md#examples).

## Примеры вопросов {#examples}

- «Что происходит на кластере billing?» — ассистент начнёт со сводки здоровья и откроет отчёты по находкам.
- «Кто держит горизонт xmin на billing и что с этим делать?»
- «Почему растёт лаг pg-3?»
- «Что грузит базу последние 15 минут?» — окно за 15 минут есть, если вкладка [[ui:diag.tools.queries]] была открыта; иначе ассистент понаблюдает за топом до 50 секунд или возьмёт статистику с момента сброса.
- «Покажи план самого тяжёлого запроса из топа и проверь, поможет ли индекс по status» — план без выполнения и гипотеза через hypopg.
- «/optimize_query r3a9f1c» или строка, скопированная кнопкой [[ui:llmAssist.ask.button]], — ассистент забирает запрос, а его предложения появляются в панели [[ui:llmAssist.panel.title]].
- «Сколько заказов в каждом статусе на тестовом стенде?» — на уровне [[ui:connections.form.llmLevels.data]] ассистент прочитает ответ инструментом `run_select`.

## Если не работает {#troubleshooting}

Клиент показывает сообщение из Glafira:

- `MCP is disabled in Glafira` — отметьте [[ui:settings.mcp.enable]] и перезапустите MCP-сервер в клиенте;
- `MCP is disabled by your organization` — MCP запрещён политикой организации;
- `Glafira did not start the MCP server within 25 s` — откройте Glafira сами, проверьте статус в разделе [[ui:settings.mcp.section]] и перезапустите сервер в клиенте;
- `bad_token` — перезапустите MCP-сервер в клиенте: Glafira выдаёт новый токен при каждом запуске сервера.

Известные ограничения: на Linux без `XDG_RUNTIME_DIR` и при длинном пути каталога данных сокет создаётся в общем `/tmp` с фиксированным именем `glafira-pg-mcp.sock` (права 0600); ошибка сервера в ответе по `queryId` из `pg_stat_statements` может содержать значения данных; ранее созданная пользовательская функция, ошибочно помеченная `IMMUTABLE`, может вычисляться при построении плана, и её результат попадёт в подробный план (изменить данные при этом нельзя: транзакция только для чтения).

Ошибки вызовов ассистент видит сам и обычно объясняет: `client_not_approved` — ответьте на диалог в Glafira; `not_allowed` — подключение закрыто для ассистента (уровень [[ui:connections.form.llmLevels.off]]) или его нет; `rate_limited` и `busy` — сработал предел (60 вызовов в минуту, одно наблюдение за раз на сессию), ассистент повторит позже; `data_not_allowed` — инструменту `run_select` нужен уровень [[ui:connections.form.llmLevels.data]], а у подключения [[ui:connections.form.llmLevels.diagnostics]]; `data_disabled` — чтение данных ограничено политикой организации; `forbidden_function`, `user_function` и `invalid_sql` — Glafira отвергла SQL ассистента, причина — в сообщении, ассистент перепишет запрос; `request_closed` — вы отменили запрос на оптимизацию; `TIMEOUT` у `run_select` — запрос не вернул ни одной строки за 10 секунд.
