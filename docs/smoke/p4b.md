# Смоук P4b: запрос на оптимизацию, предложения LLM, уровень данных и сценарии

Проверяем, что ассистент получает запрос на оптимизацию из консоли EXPLAIN и карточки запроса, его предложения появляются в
панели «Предложения LLM», планы сравниваются без выполнения, а решение пользователя видно модели; что на уровне «Диагностика и
данные» `run_select` читает данные без маскирования, отвергает опасный SQL и ничего не меняет в базе; что четыре сценария
(MCP prompts) работают в Qwen Code и Claude Code.

Как читать: у каждого шага есть **Сделать** (по порядку) и **Должно быть** (отметьте, что совпало). Вопросы ассистенту
выделены цитатой — их вводят в Qwen Code обычным текстом. Блок **Терминал** — команды и то, что они должны напечатать: их
может выполнить контроллер (Claude в терминале этого Mac), на экране владелец проверяет только пункты «Должно быть». Шаги идут
по порядку: часть шагов опирается на предыдущие.

Если что-то не так — запишите номер шага и что увидели (лучше со снимком экрана). Пригодятся:
- журнал вызовов: «Настройки» → «LLM-ассистенты (MCP)» → «Журнал» → «Обновить» (кнопка «Показать файл» открывает его на диске);
- лог приложения: `~/Library/Logs/io.github.vvnovg.glafira.postgres/app.log`.

Ответы модели зависят от модели: если она вызвала не тот инструмент или ответила не по-русски, повторите вопрос точнее
(например, «используй run_select») — ошибкой Glafira это не считается.

## Подготовка

Смоук идёт на этом Mac (M4 Pro), против стенда в OrbStack, с установленным приложением.

**Приложение.** Нужна сборка ветки `feat/p4b`, установленная в `/Applications` (как в `docs/smoke/p4a.md`, «Подготовка»):
`pnpm tauri build` в рабочей копии ветки, затем `.app` из `src-tauri/target/release/bundle/macos/` скопировать в
`/Applications` вместо прежней. Ошибка в конце сборки без `TAURI_SIGNING_PRIVATE_KEY` относится к архиву обновления —
`.app` годен. При первом подключении macOS может спросить доступ к паролю в связке ключей — «Разрешать всегда».

**Клиенты.** Qwen Code и Claude Code уже добавили сервер `glafira-pg` и подтверждены в Glafira (шаги 3 и 13 смоука P4a).
Qwen Code запускайте так же, как в P4a: `cd ~/smoke-p4a && qwen --allowed-mcp-server-names glafira-pg`; Claude Code — `claude`
в `~/smoke-p4a`. В «Настройки» → «LLM-ассистенты (MCP)» отмечено «Разрешить MCP-сервер».

**Стенд.** Поднять (никогда не `docker compose down`) из рабочей копии, где поднят стенд:

```bash
docker compose -f dev/docker-compose.yml up -d --no-recreate && scripts/wait-stand.sh
```

```bash
docker compose -f dev/docker-compose.yml up -d --no-recreate pg-perf && scripts/wait-perf.sh
```

**Подключения.** Из смоука P4a остаются `lab` (`localhost:5470`, база `orders`), `demo` (кластер Patroni, база `orders`) и
`perf` (`localhost:5471`, база `perf`) — роль `glafira_diag`, «Доступ для LLM» → «Диагностика». Если у вас они названы
иначе, берите свои и называйте их имена в вопросах ассистенту. Добавьте два подключения (кнопка «+» над деревом, окружение
`dev`, «Доступ для LLM» → «Диагностика и данные»):

| Имя | Куда | База | Роль / пароль |
|---|---|---|---|
| `lab-app` | `localhost:5470` | `orders` | `glafira_app` / `app-secret` |
| `lab-admin` | `localhost:5470` | `orders` | `postgres` / `postgres-secret` |

**Терминал.** Во всех командах ниже `$DATA` — каталог данных приложения. Задайте его в каждом новом окне терминала:

```bash
DATA="$HOME/Library/Application Support/io.github.vvnovg.glafira.postgres"
```

Запрос с плохим планом для шагов 2–9 (функция над колонкой в условии, подзапрос на каждую строку, сортировка под `LIMIT`):

```sql
SELECT o.id, o.total,
       (SELECT count(*) FROM shop.order_items i WHERE i.order_id = o.id) AS items
FROM shop.orders o
WHERE date_trunc('day', o.created_at) = date '2026-06-01'
  AND o.status <> 'done'
ORDER BY o.total DESC
LIMIT 20
```
