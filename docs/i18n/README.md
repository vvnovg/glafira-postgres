# Локализация (i18n)

Интерфейс и тексты Rust локализуются через словари `src/locales/<код>.json`: `en` — эталон ключей и параметров,
`ru` — эталон смысла. Сейчас языков два — en и ru; остальные вернутся на этапе P6 (раздел «Другие языки»).
Термины PostgreSQL и Patroni и стиль переводов — [glossary.md](glossary.md).

## Соглашение о ключах
- Вложенные объекты, ключи в camelCase: `<область>.<экран/компонент>.<смысл>`, например `settings.language.label`.
- Общие тексты — в `common.*`; ошибки из Rust — в `errors.<модуль>.<смысл>`.
- Параметры — `{{name}}`, одинаковые во всех словарях; значения не склеиваются в код (фраза целиком — один ключ).
- Видимые подписи обязательны: `aria-label`, `title`, `placeholder` тоже идут через словарь.

## Как добавить строку
1. В компоненте: `const { t } = useTranslation();` и `t("область.экран.смысл", { param })`.
2. Добавить ключ во все словари `src/locales/*.json`: `en` — эталон, `ru` — по-русски.
   Если перевод намеренно совпадает с английским (`Patroni`, `DNS / TCP`), добавить ключ в `docs/i18n/same-as-en.json`.
3. `pnpm i18n:check` — словари согласованы, нет забытой кириллицы в коде.

## Плюралы
Число рядом с существительным — только через `count` и суффиксы `_one`, `_few`, `_many`, `_other`
(набор форм — по `Intl.PluralRules`: en — `one`/`other`; ru — `one`/`few`/`many`/`other`). Пример: `sidebar.partitions_*`.
Подписи вида «участников: N» (метка: значение) плюрала не требуют.

## Тексты из Rust
- `app_err!(ErrorCode::X, "errors.m.y", "English {{p}}", p = value)` — ошибка с кодом; `ltext!("errors.m.y", "English {{p}}", p = value)` — текст.
- В IPC уходит структура `{ key, params, text }`: `text` — английский запасной вариант (его же пишут в лог).
- На фронтенде `tr(x)` (`src/i18n/text.ts`) переводит по ключу, а если ключа нет — показывает `text` как есть.
- `LocalizedText::raw(..)` — только технический текст (сообщение сервера PostgreSQL, парсера), который нельзя перевести.
- Ключи, вызванные из Rust, проверяются: `pnpm i18n:check` падает, если ключа нет в словаре.

## Проверки
`pnpm i18n:check` = `node scripts/i18n-check.mjs --require-all-languages --rust-cyrillic src-tauri/src`:
словарь есть у каждого языка из `src/i18n/languages.ts`; одинаковые ключи, параметры и теги во всех словарях;
плюральные формы под язык; строки, совпадающие с en, — только из `docs/i18n/same-as-en.json`;
ключи `ltext!`/`app_err!`; кириллица в коде фронтенда и Rust (кроме словарей и тестов). Запускать перед коммитом и в CI. Тесты скриптов — `pnpm test:scripts`.

`node scripts/i18n-check.mjs --lengths` дополнительно печатает строки, заметно длиннее английских, —
что проверить на ширине окна 1400 px и 900 px.

## Новый язык
1. Код и самоназвание — в `src/i18n/languages.ts` и в списке языков Rust (`src-tauri/src/settings.rs`); если язык ОС
   сопоставляется не по первой части тега (как `pt-PT` → `pt-BR`, `zh-HK` → `zh-TW`), — правило в `match_language_in`.
2. Столбец в таблицах `glossary.md` и строка в «Стиль по языкам», затем `src/locales/<код>.json` переводом `en.json`.
3. `pnpm i18n:check`, `pnpm vitest run src/i18n/locales.test.ts`; вручную — переключение языка, `lang` документа, сопоставление языка ОС.
4. Главы `docs/guide/<код>/*.md` — все из `GUIDE_CHAPTERS`, переводом: копия en не проходит `pnpm i18n:check` («глава не переведена»), поэтому словарь и главы нового языка приходят вместе.

## Подсказки
Значок «?» — компонент `<Hint k="hints.<экран>.<поле>" label={t("…подпись…")} />` (`src/components/common/Hint.tsx`).
Значок не ставится внутри `<label>`: рядом с подписью в обёртке `<span className="field-label">` или сразу после `</label>`.
Текст — 1–2 фразы: что это и когда что выбирать; en не длиннее 200 символов; параметры и значения PostgreSQL и Patroni — в `<code>`.
Новая подсказка: ключ во всех словарях (раздел `hints`, последний ключ верхнего уровня) и значок в коде.
`pnpm i18n:check` не пропустит ключ без значка, значок без ключа и слишком длинный en-текст.
Ключ, выбираемый по состоянию, — статическими литералами в таблице, а не шаблонной строкой.

## Руководство
Главы — `docs/guide/<код>/<глава>.md` (набор глав — `GUIDE_CHAPTERS` в `scripts/i18n-check.mjs`), одинаковый у всех языков;
термины в тексте — по [glossary.md](glossary.md).
Глава начинается с `# Заголовок`, разделы — `## Заголовок {#id}` (id одинаковые во всех языках), элементы интерфейса —
метками `[[ui:ключ]]` (ключ без `{{…}}`), ссылки между главами — `[текст](глава.md#якорь)`, внешние — только `https://`.
Якорь `{#id}` — только у `##` и у каждого `##`, без повторов в главе. Точку сразу после метки рендер убирает,
если значение уже кончается на «.» или «:» — писать `[[ui:ключ]].` в конце фразы можно в любом языке.
`pnpm i18n:check` проверяет главы, якоря, метки и ссылки, а также что метка со значением, которое начинается или кончается
пунктуацией, не стоит вплотную к букве: `**…**` там по CommonMark не становится жирным.

## Псевдоязык
В dev-сборке (`pnpm tauri dev`) в «Настройки» → «Язык» есть пункт «Pseudo (dev)»: все строки показываются как `[!! … !!]`
с диакритикой и удлинением. Строки без скобок — забытые; сломанная вёрстка — узкие места. Выбор не сохраняется.

## Другие языки
На этапе P6 вернутся de, fr, es, it, pl, pt-BR, zh-CN, zh-TW, ja, ko. Скрипт `scripts/i18n-check.mjs` уже умеет проверять
их типографику (неразрывные пробелы и `…` во французском; полуширинную пунктуацию и пробелы между иероглифами в zh/ja),
а `Intl.PluralRules` даёт набор плюральных форм. Столбцы в `glossary.md`, правила письма для каждого языка и главы руководства
добавляются вместе с языком (см. «Новый язык»). Скрипты не заменяют носителя: перед выпуском язык просматривает носитель.
