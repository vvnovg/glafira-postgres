# LLM-ассистенты (MCP)

Glafira может работать шлюзом для LLM-ассистента: Qwen Code, Claude Code, Claude Desktop, Cursor или другого клиента с поддержкой MCP (Model Context Protocol). Ассистент читает диагностику подключений, которые вы ему открыли, — топологию, отчёты инструментов с находками, активность, топ запросов, карточки запросов, таблицы, параметры сервера, планы без выполнения — и проверяет гипотезы индексов через hypopg. Медленный запрос из консоли EXPLAIN или карточки запроса можно передать ему на оптимизацию: переписанный запрос и индексы возвращаются в панель, где вы сравниваете планы (см. [Запрос на оптимизацию и предложения](llm-mcp.md#optimization)). Такой запрос Glafira может и сама передать Qwen Code или Claude Code, запустив агента в фоне, без чата (см. [Фоновый ассистент](llm-mcp.md#background)). На тестовых стендах ему можно разрешить и чтение данных через `SELECT` (см. [Уровень «Диагностика и данные»](llm-mcp.md#data-level)). Изменить базу через Glafira он не может: отмену и завершение сессий, удаление слотов, switchover и перезапуск, создание индексов и правку запросов вы делаете сами, а ассистент подсказывает, что и где сделать.

## Как это устроено {#how-it-works}

Клиент запускает `glafira-pg mcp` — тот же файл приложения в режиме без окна. Команда находит запущенную Glafira по файлу `mcp.json` в папке данных, соединяется с ней через локальный сокет (на Windows — именованный канал) и передаёт ей запросы ассистента. Glafira отвечает через свои подключения: пароли, ключи SSH и строки подключения остаются в ней, ассистент их не получает.

Сокет доступен только вашему пользователю. Для входа нужен токен, который Glafira записывает в `mcp.json` при каждом запуске сервера; файл доступен только владельцу и существует, пока сервер работает.

## Включение {#enable}

1. Откройте [[ui:sidebar.settings]], раздел [[ui:settings.mcp.section]].
2. Отметьте [[ui:settings.mcp.enable]]. Статус сменится на [[ui:settings.mcp.state.running]].
3. Откройте форму подключения ([[ui:sidebar.editConnection]] в меню подключения), выберите [[ui:connections.form.llmLevels.diagnostics]] в группе [[ui:connections.form.llmAccess]] и сохраните. В дереве у подключения появится значок `LLM`. Третий уровень, [[ui:connections.form.llmLevels.data]], — для тестовых стендов: см. [Уровень «Диагностика и данные»](llm-mcp.md#data-level).

По умолчанию MCP выключен, а у каждого подключения уровень [[ui:connections.form.llmLevels.off]]: такие подключения ассистент не видит. Уровень не переносится при экспорте и импорте подключений: импортированное подключение закрыто для ассистента, пока вы не откроете его сами. Смена уровня не переоткрывает соединение. Флажок [[ui:common.readOnly]] на доступ ассистента не влияет: ассистент ничего не меняет. Окружение `prod` тоже ничего не запрещает; на уровне [[ui:connections.form.llmLevels.data]] форма только предупреждает: [[ui:connections.form.llmProdWarning]].

Если MCP уже обслуживает другое окно Glafira, статус — [[ui:settings.mcp.state.otherInstance]]; клиенты подключаются к тому окну.

## Подключение клиента {#connect-client}

В блоке [[ui:settings.mcp.connect.title]] — готовые фрагменты с путём к установленному приложению и кнопками копирования:

- Qwen Code — команда `qwen mcp add glafira-pg "<путь>" mcp` или блок `mcpServers` для файла `~/.qwen/settings.json`;
- Claude Code — команда `claude mcp add glafira-pg -- "<путь>" mcp`;
- Claude Desktop — блок для файла `claude_desktop_config.json`; после правки перезапустите Claude Desktop;
- Cursor — блок для файла `~/.cursor/mcp.json`;
- любой другой клиент, который запускает MCP-сервер командой (stdio), — команда и аргумент `mcp`.

Клиент может работать и с моделью на вашем компьютере, без облака, — об этом глава [Локальные модели](local-llm.md).

Сначала откройте Glafira, потом запускайте клиент. Если Glafira закрыта, команда `glafira-pg mcp` запустит её сама и подождёт до 25 секунд, но клиенты ждут ответа сервера недолго (Qwen Code — 30 секунд), и при медленном запуске подключение может не успеть. Если вы переустановили Glafira в другое место, скопируйте фрагмент заново.

Где клиент хранит сервер, зависит от его области (scope). Claude Code по умолчанию добавляет сервер в область `local` — только для текущего проекта; чтобы glafira-pg был доступен во всех проектах, добавьте `--scope user` (`-s user`) перед именем: `claude mcp add --scope user glafira-pg -- "<путь>" mcp`. Qwen Code по умолчанию использует область `user` (всем проектам); `-s project` ограничивает сервер текущим проектом. Остальные флаги — в `claude mcp add --help` и `qwen mcp add --help`.

## Подтверждение клиента {#approve}

Когда клиент подключается впервые, Glafira поверх любого экрана показывает диалог: имя и версия клиента и сколько подключений открыто для LLM-ассистентов. Нажмите [[ui:mcp.approval.allow]] или [[ui:mcp.approval.reject]]; Escape — тоже отказ. Пока вы не ответили, ассистент получает ошибку `client_not_approved` и просит ответить в окне Glafira. Если ждут несколько клиентов, диалоги идут по очереди. Сессии фонового ассистента подтверждение не нужно: см. [Что видит фоновый агент](llm-mcp.md#background-scope).

Разрешённый клиент запоминается по имени и появляется в списке [[ui:settings.mcp.clients.title]]. Отказ не запоминается: при следующем подключении Glafira спросит снова. Клиент без имени показывается как [[ui:mcp.unknownClient]], и разрешение действует только до конца его сессии.

Имя клиента может подделать любая программа на вашем компьютере: подтверждение показывает, кто подключился, а защищает токен в файле `mcp.json`, доступном только вашему пользователю.

## Что видит ассистент {#access}

С уровнем [[ui:connections.form.llmLevels.diagnostics]] ассистент получает:

- открытые подключения (имя, окружение, вид, папка, уровень, база по умолчанию) и их топологию: узлы с ролями, лагом и таймлайном, состояние Patroni, события топологии;
- сводку здоровья: пульс и находки быстрых инструментов (сессии, блокировки, горизонт xmin, реплики, слоты, у Patroni — готовность к failover и health);
- отчёт любого инструмента группы [[ui:sidebar.diagnostics]] с находками и текстами «что сделать»;
- активность: сессии с фильтрами и наблюдение за ними до 50 секунд — ожидания, главные запросы, появившиеся и ушедшие сессии;
- топ запросов `pg_stat_statements` — с момента сброса, за окно (если вкладка [[ui:diag.tools.queries]] уже копила историю) или наблюдением до 50 секунд — и карточку запроса;
- таблицу: колонки, индексы, ограничения, статистику, DDL и статистику колонок `pg_stats` без значений (ответ говорит ассистенту, что частые значения и гистограммы есть только на уровне [[ui:connections.form.llmLevels.data]]);
- параметры сервера из `pg_settings`: пароли в строках подключения (в том числе в виде URI) и в командах (`primary_conninfo`, `archive_command` и других) заменены на `***`, `ssl_passphrase_command` и параметры с «секретными» именами (в том числе у расширений) скрыты целиком; строки с источником `client` и `session` — это настройки собственного соединения Glafira, а не сервера;
- план запроса без выполнения (EXPLAIN без ANALYZE) с рекомендациями и проверку гипотезы индекса через hypopg — до пяти индексов за раз; без расширения hypopg ассистент получит подсказку, как его включить.

На уровне [[ui:connections.form.llmLevels.data]] ассистент получает всё это без маскирования, а кроме того значения из `pg_stats` и чтение данных инструментом `run_select`: см. [Уровень «Диагностика и данные»](llm-mcp.md#data-level).

SQL ассистента проверяется до отправки на сервер: принимается ровно одна инструкция `SELECT`, `INSERT`, `UPDATE`, `DELETE` или `MERGE` (без ANALYZE она не выполняется), а служебные команды и опасные функции (`pg_sleep`, `dblink`, `lo_import`, `set_config`, сигналы, сбросы статистики `pg_stat_reset*`, `ts_stat`, `ts_rewrite`, файловые функции и другие) отвергаются. План строится в транзакции только для чтения, которая всегда откатывается, на отдельном соединении с `application_name = glafira-pg-mcp`; сессия MCP к тому же начинается с `default_transaction_read_only = on`. Ошибки позиции в SQL указывают на исходный текст ассистента. У инструмента `run_select` правила строже — они описаны в разделе [Уровень «Диагностика и данные»](llm-mcp.md#data-level).

Ответы сжаты, чтобы поместиться в контекст локальной модели: пустые поля опущены, дробные числа округлены, в строках топа запросов нет нулевых счётчиков и текст обрезан до 500 символов (полный — в карточке запроса), история в карточке — не больше 12 точек, в профиле ожиданий нет интервалов без образцов, а подряд идущие интервалы простоя сведены в один. Размер ответов ограничен: ответ — до 100 КБ, в карточке запроса — не больше 20 выполняющихся экземпляров (с общим числом), в карточке таблицы — не больше 200 секций (с общим числом), текст запроса сессии — до 2 КБ. Ошибки SSH-туннеля ассистенту показываются общим текстом, без адреса бастиона, а ошибки узлов в отчётах — без подробностей и путей.

Ассистент никогда не получает пароли и секреты хранилища, настройки SSH, строки подключения профилей, журнал действий, журнал MCP и настройки приложения. Метрик ОС и логов сервера в Glafira нет — их ассистент попросит у вас.

Тексты запросов, комментарии и имена объектов приходят из базы и могут быть заданы кем угодно. Glafira предупреждает ассистента, что это данные, а не инструкции.

## Маскирование {#masking}

На уровне [[ui:connections.form.llmLevels.diagnostics]] Glafira заменяет литералы в текстах запросов на `$1`, `$2`… до того, как отдать их ассистенту: строки, числа, `E'…'`, строки в долларовых кавычках и другие. Тело комментария заменяется на `/*…*/` (в комментариях бывают данные, например теги sqlcommenter); метка `/* glafira */` остаётся. Маскируются тексты `pg_stat_activity` во всех инструментах, тексты `pg_stat_statements`, выполняющиеся экземпляры в карточке запроса и условия в узлах плана (`Filter`, `Index Cond` и другие) у планов, построенных не по SQL ассистента. Сколько литералов замаскировано, видно в журнале.

Не маскируются SQL, который прислал сам ассистент, и его план, DDL таблиц (значения по умолчанию и `CHECK` — это схема), имена объектов, ролей и приложений, а также снимок запроса на оптимизацию — его отправляете вы сами (на любом уровне, см. [Запрос на оптимизацию и предложения](llm-mcp.md#optimization)). Данные, вписанные в имена, маскирование не распознаёт. Текст, обрезанный сервером посередине литерала, маскируется до конца.

Маскирование не зависит от настройки `standard_conforming_strings` узла: текст маскируется при обоих её значениях, и если границы литералов получаются разными, ассистент получает только общее начало и одну метку `$N…` вместо остатка. Поиск по тексту (параметр `search` у `get_top_queries` и в списке запросов) на уровне [[ui:connections.form.llmLevels.diagnostics]] ищет по замаскированному тексту среди первых 200 строк топа, поэтому значения литералов найти нельзя.

На уровне [[ui:connections.form.llmLevels.data]] Glafira ничего не маскирует ни в одном инструменте.

## Сессии, отзыв и журнал {#sessions-log}

Пока клиент подключён, внизу боковой панели виден индикатор `LLM` с именем клиента (или числом клиентов); во время вызова он подсвечивается. Щелчок открывает раздел MCP в настройках.

- [[ui:settings.mcp.sessions.title]] — клиент, начало и число вызовов; [[ui:settings.mcp.sessions.disconnect]] закрывает одну сессию, [[ui:settings.mcp.sessions.disconnectAll]] — все.
- [[ui:settings.mcp.clients.title]] — [[ui:settings.mcp.clients.revoke]] забывает клиента и закрывает его сессии; при следующем подключении он снова попросит подтверждение.
- Новый уровень в форме подключения, отзыв клиента и выключение MCP действуют со следующего вызова ассистента; переподключать клиент не нужно.
- [[ui:settings.mcp.audit.title]] — последние 200 записей: время, клиент, инструмент или событие, подключение, итог, длительность, число замаскированных литералов (у `run_select` — число строк). Аргументы длиннее 1 КБ обрезаются, SQL записывается целиком до 16 КБ, ответы и значения, прочитанные `run_select`, не записываются. События [[ui:settings.mcp.audit.events.requestCreated]] и [[ui:settings.mcp.audit.events.proposalAnswered]] приходят от [запросов на оптимизацию](llm-mcp.md#optimization). События [[ui:settings.mcp.audit.events.agentRunStarted]] и [[ui:settings.mcp.audit.events.agentRunFinished]] пишет [фоновый ассистент](llm-mcp.md#background-runs). [[ui:settings.mcp.audit.reveal]] открывает файл `mcp-audit.jsonl`.
- У успешного вызова `explain_query` или `run_select` кнопка [[ui:settings.mcp.audit.openInConsole]] открывает [консоль EXPLAIN](queries.md#console) подключения с тем же SQL, базой и узлом (если вызов пришёл без базы — с базой подключения по умолчанию). Ничего не запускается: постройте план сами и сравните с тем, что видел ассистент. Кнопка недоступна, если аргументы в журнале обрезаны, вызов задан `queryId`, подключения больше нет или доступ для LLM у него выключен; причина — в подсказке кнопки.

Чтобы выключить MCP совсем, снимите флажок [[ui:settings.mcp.enable]]: клиенты отключатся, файл `mcp.json` удалится.

## Политика организации {#policy}

Администратор может запретить MCP ключом политики `mcpEnabled`: флажок [[ui:settings.mcp.enable]] недоступен с пометкой [[ui:settings.mcp.policy]], сервер не запускается, а команда `glafira-pg mcp` завершается с ошибкой. Ключ `mcpMaxAccess` ограничивает уровень доступа сверху; при потолке `diagnostics` в разделе MCP написано [[ui:settings.mcp.dataPolicy]], подключения с уровнем [[ui:connections.form.llmLevels.data]] работают как [[ui:connections.form.llmLevels.diagnostics]] (тексты снова маскируются, `pg_stats` — без значений), в их форме написано [[ui:connections.form.llmDataAsDiagnostics]], а `run_select` отвечает `data_disabled`. Если политика не читается или у этих ключей неверное значение, MCP тоже запрещён, а ошибка видна в окне [[ui:sidebar.about]]. Ключ `mcpAgentEnabled` запрещает только фонового ассистента: [[ui:settings.mcp.agent.enable]] недоступен с пометкой [[ui:settings.mcp.policy]], а [[ui:llmAssist.ask.button]] копирует строку для чата; `mcpEnabled = false` запрещает и его. Подробности — в руководстве администратора.

## Запрос на оптимизацию и предложения {#optimization}

В консоли EXPLAIN (режим [[ui:diag.explain.sourceSql]], рядом с кнопками плана) и в карточке запроса (в ряду под текстом запроса) есть кнопка [[ui:llmAssist.ask.button]]. Она создаёт запрос на оптимизацию — снимок запроса для LLM-ассистента: узел, базу, текст, значения параметров последнего плана (в консоли), статистику `pg_stat_statements` (в карточке), план в виде текста и DDL таблиц. Если для текущих текста, узла и базы плана ещё нет, Glafira пробует построить его без выполнения. Под кнопками появляется сообщение: запрос r3a9f1c передан, скажите ассистенту «оптимизируй запрос из Glafira» — он заберёт его сам. Так и напишите в Qwen Code, Claude Code или другом подключённом клиенте: id называть не нужно, без него ассистент берёт последний ожидающий запрос. Строка с id на языке интерфейса, например «Оптимизируй запрос r3a9f1c из Glafira», уже в буфере обмена — вставьте её, если ответа ждут несколько запросов. Снимок модель забирает инструментом `get_optimization_request`. Если включён [фоновый ассистент](llm-mcp.md#background), кнопка вместо этого ставит запрос в его очередь и ничего не копирует.

Рядом стоит кнопка [[ui:diag.query.copyLlm]] (см. [Карточка запроса](queries.md#card)): она копирует то же содержимое текстом для любого чата, MCP ей не нужен, но ответ модели в Glafira не вернётся. Запрос кнопки [[ui:llmAssist.ask.button]] ассистент с MCP забирает сам, может проверить планы и индексы через Glafira и возвращает предложения в панель [[ui:llmAssist.panel.title]]. Эту разницу объясняет и значок «?» у каждой из кнопок.

Снимок уходит модели как есть, без маскирования литералов, даже если подключение открыто только для диагностики: его отправляете вы сами, а в плане могут быть значения из формы параметров. Кнопка недоступна, пока MCP-сервер выключен или работает в другом окне Glafira, политика запрещает MCP или подключение закрыто для LLM-ассистентов; значок «?» рядом объясняет причину и где это включить. В карточке кнопка появляется, когда текст запроса известен и не обрезан; запрос длиннее 64 КБ передать нельзя.

Пока модель работает, под кнопками консоли и карточки видна строка «Ждёт ответа LLM: запрос r3a9f1c» с кнопкой [[ui:llmAssist.ask.cancel]]: отменённый запрос модели больше не отдаётся, она получает `request_closed`. Новый запрос из той же консоли или из карточки того же запроса можно отправить, когда прежний получил ответ или отменён. Glafira хранит последние 50 запросов. Большой снимок урезается, чтобы уложиться в ответ 100 КБ: первыми уходят DDL последних таблиц и конец текста плана, а модель получает пометку, что опущено, и может прочитать это через `get_table_details` и `explain_query`.

Модель отвечает инструментом `propose_query_rewrite`: переписанный запрос, до пяти `CREATE INDEX`, обоснование (до 4 КБ) и ожидаемый эффект (до 1 КБ). Перед сохранением Glafira проверяет предложение: вид инструкции тот же, что у исходной; запрещённых функций нет; индексы проходят те же проверки, что у `hypothetical_index` (без `CONCURRENTLY` и `UNIQUE`, имя индекса отбрасывается); сервер может спланировать запрос (`prepare` и план без выполнения в транзакции `READ ONLY`, которая всегда откатывается, на узле запроса). Ошибку модель получает с текстом сервера и исправляет запрос сама. Переписанный запрос Glafira не выполняет и индексы не создаёт. Повтор того же предложения дубля не создаёт; на один запрос — не больше пяти предложений. Модель может предложить переписать запрос и по своей инициативе, без запроса из Glafira, например найдя его в топе: такое предложение появляется в консоли его подключения, когда в ней выбрана та же база.

Панель [[ui:llmAssist.panel.title]] под редактором консоли показывает предложения на запросы этой консоли и предложения без запроса для выбранной базы; пока предложений нет, она свёрнута. Новое предложение появляется сразу; если консоль на фоновой вкладке, у вкладки загорается точка. В списке у каждого предложения — статус, клиент, время и первая строка предложенного текста. Статус написан словом и выделен цветом: [[ui:llmAssist.panel.status.new]] — синим, [[ui:llmAssist.panel.status.accepted]] — зелёным, [[ui:llmAssist.panel.status.rejected]] — красным. Выбранное предложение открывается карточкой. В её шапке — статус, клиент и время, справа — кнопки [[ui:llmAssist.panel.accept]] и [[ui:llmAssist.panel.reject]], ниже — [[ui:llmAssist.panel.compare]], [[ui:llmAssist.panel.openInConsole]] и [[ui:llmAssist.panel.copy]]; причина отклонения — отдельной строкой под статусом. Дальше идут исходный и предложенный текст рядом с подсветкой изменённых строк и постоянная пометка: Glafira не проверяет, что переписанный запрос возвращает те же строки. Затем — обоснование и ожидаемый эффект как обычный текст (разметку модели панель не применяет) и индексы. В колонке [[ui:llmAssist.panel.original]] может стоять `$1::timestamptz` там, где в карточке запроса `timestamptz $1`: так `pg_stat_statements` записывает типизированные литералы, сервер такой текст не планирует, и Glafira хранит и сравнивает исходный и предложенный текст с приведениями `$N::тип`.

- [[ui:llmAssist.panel.compare]] строит оба плана без выполнения на узле предложения с теми же значениями параметров; предложенный запрос планируется вместе с его индексами через `hypopg` (виртуальные индексы живут только в сессии сравнения, см. [Рекомендации по плану](queries.md#recommendations)). Итог — стоимость «была / стала», горячие узлы обоих планов, рекомендации к обоим и используется ли каждый индекс. Если в базе нет `hypopg`, сравнение идёт без индексов, и это помечено. Запрос с `$1`, `$2`… без сохранённых значений сравнивается по общему плану, а для него нужен PostgreSQL 16 или новее; на более старых версиях сравните такой запрос в консоли со своими значениями. Сравнение идёт собственным соединением EXPLAIN Glafira, как в консоли. Итог сохраняется в предложении, и модель видит его в `list_proposals`.
- [[ui:llmAssist.panel.openInConsole]] подставляет предложенный текст в консоль вместе с базой и узлом предложения. Заменённый текст попадает в список [[ui:diag.explain.replaced.title]] под панелью (последние 10 текстов), откуда его возвращает кнопка; так же работает открытие запроса из журнала MCP. Дальше действуют обычные правила консоли, в том числе [план с выполнением](queries.md#analyze).
- [[ui:llmAssist.panel.accept]] и [[ui:llmAssist.panel.reject]] записывают ваше решение; к отклонению можно добавить причину до 500 символов — модель увидит её в `list_proposals`. Решение можно поменять позже. [[ui:llmAssist.panel.copy]] копирует предложенный текст. Применить изменение — поправить код приложения, создать индекс — предстоит вам самим.

В карточке запроса, в ряду под текстом запроса, после кнопки [[ui:llmAssist.ask.button]] появляется ссылка «Предложения LLM: N — открыть в консоли». Она считает предложения к этому запросу (по его `queryid` и по запросам, отправленным из карточки) и открывает консоль с исходным текстом и панелью, где выбрано самое свежее предложение (сначала — без ответа).

Предложения хранятся в `llm-proposals.json` в каталоге данных приложения (до 100, до пяти на запрос), запросы — в `llm-requests.json`; оба файла доступны только вашему пользователю. Журнал MCP записывает создание запроса и ваши ответы на предложения — без текста запроса и причины.

## Уровень «Диагностика и данные» и run_select {#data-level}

Третий уровень доступа для LLM в форме подключения, [[ui:connections.form.llmLevels.data]], рассчитан на стенды нагрузочного тестирования и тестовые базы. На нём модель видит всё, что и на уровне диагностики, но без маскирования ни в одном инструменте (тексты запросов, тексты сессий и планы — со значениями), получает частые значения и гистограммы колонок из `pg_stats` в `get_table_details` (значения длиннее 2 КБ обрезаются) и читает данные инструментом `run_select`. В дереве у такого подключения значок `LLM` заполнен. Если окружение подключения — `prod`, форма предупреждает, что данные production-базы будут уходить провайдеру LLM; это предупреждение, а не запрет. Если политика организации ограничивает доступ уровнем диагностики (`mcpMaxAccess`), подключение работает как [[ui:connections.form.llmLevels.diagnostics]], и форма об этом пишет.

`run_select` принимает ровно одну инструкцию `SELECT` (в том числе `VALUES`, `TABLE`, `WITH … SELECT`) без `INTO`, `FOR UPDATE` / `FOR SHARE` и изменяющих CTE на любой глубине и без параметров вида `$1`: значения пишутся прямо в текст запроса. База необязательна (по умолчанию — база подключения), узел тоже: без него запрос идёт на доступную реплику с наименьшим лагом, а если её нет — на лидера. Glafira проверяет запрос в несколько слоёв:

- дерево разбора `pg_query` и список запрещённых функций: административные, доступ к файлам, большие объекты, `dblink`, `http`, `set_config`, advisory-блокировки, `pg_sleep`, `pg_notify`, `query_to_xml` и родственные, функции расширений, которые выполняют SQL из строки (`pg_background`, `crosstab`, `connectby`, `xpath_table`, `pgr_*` из pgRouting), и все функции схем `net` (pg_net), `aws_s3` и `aws_lambda`, которые обращаются за пределы базы, — ошибка `forbidden_function`;
- отдельное соединение с `application_name = glafira-pg-mcp` и транзакция `BEGIN READ ONLY`, которая всегда откатывается, со `statement_timeout` 10 с и `lock_timeout` 1 с;
- сверка вызванных функций с `pg_proc` — сначала по именам в запросе, затем по пробному `EXPLAIN (VERBOSE)`, который показывает и функции, вызванные через представление или запись `t.f`: функция вне `pg_catalog`, не принадлежащая расширению, — пользовательская, её тело проверить нельзя, и `run_select` её отвергает (`user_function`); проба находит и запрещённые функции, не видные разбору. Функции расширений, например `pg_stat_statements` или PostGIS, разрешены, если их нет в списке.

Запрос выполняется курсором: по умолчанию 100 строк, не больше 500 (`maxRows`) и не больше 100 КБ ответа; значения обрезаются на сервере, и значение длиннее 2 КБ заканчивается пометкой `…[truncated]`; `truncated: true` в ответе значит, что строк было больше. На запрос отведено 10 секунд: когда они истекают, модель получает уже собранные строки, а если строк нет — `TIMEOUT`; открытие соединения в эти 10 секунд не входит, поэтому вызов может длиться чуть дольше. Если клиент отменяет вызов, Glafira останавливает запрос на сервере. В журнал MCP пишется текст запроса и число строк, значения — нет.

Проверки не делают роль подключения безопасной: функция расширения, оператор или приведение типа могут вызвать то, чего нет в списке, а `READ ONLY` не останавливает нетранзакционные действия, например сигналы другим сессиям. Поэтому у подключений с уровнем [[ui:connections.form.llmLevels.data]] в [чек-листе готовности](connections.md#readiness) есть пункт [[ui:readiness.llmRole.title]]: если роль подключения — суперпользователь или член `pg_signal_backend`, `pg_write_all_data`, `pg_read_server_files` или `pg_execute_server_program`, пункт предупреждает, что модель смогла бы сделать через `run_select`, если обойдёт список, и даёт SQL роли для стенда; то же предупреждение видно под уровнем в форме. Модель получает его полем `roleWarning` в `list_connections`, когда подключение проверено кнопкой [[ui:connections.form.test]] или выполнило `run_select` после запуска Glafira. Уровень предупреждение не выключает. Для стенда достаточно отдельной роли только для чтения:

```sql
CREATE ROLE glafira_llm LOGIN PASSWORD '…';
GRANT pg_monitor TO glafira_llm;         -- статистика для инструментов диагностики
GRANT pg_read_all_data TO glafira_llm;   -- PostgreSQL 14 и новее
-- В PostgreSQL 13 pg_read_all_data нет: в каждой базе, для каждой схемы, которую может читать модель
-- GRANT USAGE ON SCHEMA public TO glafira_llm;
-- GRANT SELECT ON ALL TABLES IN SCHEMA public TO glafira_llm;
```

Заведите с этой ролью отдельное подключение с уровнем [[ui:connections.form.llmLevels.data]], а основное оставьте на уровне [[ui:connections.form.llmLevels.diagnostics]].

## Сценарии (prompts) {#prompts}

Glafira даёт MCP-клиентам четыре готовых сценария (MCP prompts). Клиенты показывают и вызывают их по-своему:

- Qwen Code (проверено на 0.26.5) — слэш-командами с пометкой `[MCP]`: `/optimize_query`, `/triage_incident` и так далее; аргументы задаются по имени: `/analyze_top_queries --connectionId="…" --windowS="900"`.
- Claude Code (проверено на 2.1.319) показывает их в меню как `/glafira-pg:optimize_query (MCP)`, а вызывает командой `/mcp__glafira-pg__optimize_query` (набранная `/glafira-pg:optimize_query` даёт «Unknown command»); аргументы — через пробел в объявленном порядке, каждый — одно слово (Claude Code делит строку по пробелам), например `/mcp__glafira-pg__analyze_top_queries <connectionId>`. Как пропустить необязательный аргумент в середине, документация Claude Code не говорит, поэтому, чтобы задать `windowS`, укажите и `member` (имя узла): `/mcp__glafira-pg__analyze_top_queries <connectionId> <member> 900`.
- Другие клиенты — в своём списке подсказок, если вообще поддерживают MCP prompts.

Тексты сценариев — на английском. Они просят модель отвечать на языке пользователя и коротко: сначала итог до 10 строк (что происходит, вероятная причина, следующее действие), подробности — по просьбе. В `triage_incident`, `analyze_top_queries` и `review_config` модель советует, что сделать в Glafira, называя её экраны и кнопки, а не инструменты. `connectionId` — id подключения из `list_connections`; если вместо него указать имя подключения, первый вызов инструмента ответит `not_allowed` с советом вызвать `list_connections`, где ассистент может найти id. Id и имена узлов — одна строка до 128 символов, `symptom` — до 1000 символов, `windowS` — 300, 900 или 3600.

- `optimize_query` (аргумент `requestId`, необязательный: без него — последний ожидающий запрос): забирает запрос на оптимизацию, разбирает план и статистику, при необходимости проверяет гипотезы через `explain_query` и `hypothetical_index`, присылает одно или несколько предложений через `propose_query_rewrite` и коротко объясняет их в чате; дальше сравните планы в Glafira.
- `triage_incident` (`connectionId`, необязательный `symptom`): `get_health_summary`, затем не больше трёх `run_diagnostic` по находкам, которым нужны подробности (блокировки, горизонт xmin, репликация, слоты, у Patroni — готовность к failover и health), при нагрузке — `observe_activity` на 30 с; итог — что происходит, вероятные причины, что сделать в Glafira (какой экран, какое действие) и что проверить вне её (логи сервера, ОС).
- `analyze_top_queries` (`connectionId`, необязательные `member` и `windowS`, по умолчанию 900): топ из 10 запросов за окно (без накопленной истории — `observe_top_queries` на 50 с или статистика с момента сброса), карточки и планы не больше трёх главных запросов — по одному, рекомендации; кандидатов на переписывание модель присылает через `propose_query_rewrite`, и они появляются в панели консоли подключения.
- `review_config` (`connectionId`, необязательный `member`): изменённые и ключевые настройки (память, чекпойнты и WAL, autovacuum, таймауты, `track_io_timing`, `jit`, параллельность) с учётом числа соединений и нагрузки; рекомендации с рисками и пометкой, нужен ли перезапуск. Для Patroni модель предлагает правку через `patronictl edit-config`; Glafira конфигурацию не меняет.

Сценарии не обязательны: обычный вопрос в чате тоже работает, см. [Примеры вопросов](llm-mcp.md#examples).

## Фоновый ассистент {#background}

Кнопка [[ui:llmAssist.ask.button]] может обойтись без чата. При включённом фоновом ассистенте Glafira сама запускает Qwen Code или Claude Code без окна — по запуску на каждый запрос: агент забирает запрос через MCP-шлюз, проверяет идеи через `explain_query` и `hypothetical_index`, присылает предложения через `propose_query_rewrite` и завершается, а предложения появляются в панели [[ui:llmAssist.panel.title]], как обычно. Каждый запуск начинается со свежего контекста. Очередь, сроки и процессы держит Glafira, а база по-прежнему не меняется: ни агент, ни Glafira не выполняют предложенный SQL и не создают индексы.

Как включить:

1. Откройте [[ui:sidebar.settings]], раздел [[ui:settings.mcp.section]], и проверьте, что отмечено [[ui:settings.mcp.enable]]: фоновый ассистент работает через тот же шлюз.
2. В подразделе [[ui:settings.mcp.agent.title]] выберите агента — Qwen Code 0.26 или новее либо Claude Code 2.1 или новее — и нажмите [[ui:settings.mcp.agent.find]]. На macOS и Linux Glafira спрашивает вашу логин-оболочку, где лежит `qwen` или `claude` (приложение, запущенное из Dock или меню рабочего стола, не видит `PATH` оболочки), затем смотрит в `PATH` оболочки и в обычных местах: `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`, `~/.claude/local`. На Windows — в `PATH` (файлы `.exe` и `.cmd`), `%APPDATA%\npm` и `%USERPROFILE%\.local\bin`. Путь и версия показываются. Путь можно поправить руками: когда вы уходите из поля, Glafira спрашивает у программы её версию. Версия ниже минимальной получает предупреждение, а программа, которая не ответила на `--version`, — «Версию не узнать: …».
3. Выберите модель. У Qwen Code список берётся из `modelProviders` файла `~/.qwen/settings.json` (Glafira файл только читает); пустое поле — модель из настроек самого Qwen Code, та же, что в чате, и строка под полем её называет. У Claude Code флажок [[ui:settings.mcp.agent.viaOllama]] берёт список из Ollama и направляет Claude Code к ней, и тогда модель обязательна; без него модель вводится руками (пусто — модель Claude Code по умолчанию), а [[ui:settings.mcp.agent.budget]] ограничивает расходы одного запуска (по умолчанию 1 $; пусто — без предела).
4. Нажмите [[ui:common.save]], отметьте [[ui:settings.mcp.agent.enable]] (выключатель сохраняется сразу) и нажмите [[ui:settings.mcp.agent.check]]. Проверка работает по сохранённым настройкам, поэтому, пока есть несохранённые изменения, она недоступна. Короткий запуск просит агента вызвать `list_connections` и ответить OK; итог — например, «Работает: Qwen Code 0.26.5, qwen3.6-64k:35b-a3b, 23 с» — или «Не работает: …» и [[ui:llmAssist.agent.showLog]]. Проверка проходит программу, модель, MCP-конфигурацию и билет запуска.

После этого [[ui:llmAssist.ask.button]] создаёт запрос, ставит запуск в очередь и в буфер обмена ничего не кладёт; под кнопками написано «Запрос r3a9f1c передан фоновому ассистенту». Значок «?» рядом с кнопкой называет агента, которого запустит Glafira, и напоминает, что снимок уходит модели агента без маскирования. Если фоновый ассистент выключен, запрещён политикой или не настроен (не задан путь к программе, а у Claude Code через Ollama — модель), кнопка работает, как описано в разделе [Запрос на оптимизацию и предложения](llm-mcp.md#optimization). Выключатель недоступен, пока MCP-сервер выключен или работает в другом окне Glafira; путь и модель можно подготовить заранее.

Секретов агента Glafira не хранит. Агент работает с окружением вашей логин-оболочки, которое Glafira читает один раз за сеанс, поэтому до него доходят `node`, ключи API и прокси из профиля оболочки; если оболочка не ответила за 5 секунд, агент получает окружение самой Glafira. Если каталога программы нет в этом `PATH`, Glafira дописывает его в конец — так `qwen`, установленный через `nvm`, находит свой `node`. Облачный Claude Code входит своей подпиской или своим ключом, а Qwen Code берёт ключ из своих настроек. Поверх этого Glafira добавляет только пресет: флаги, постоянные для каждого агента (MCP-конфигурация запуска, выключенные встроенные инструменты, выключенные пользовательские настройки агента, одобрение инструментов Glafira, пределы, модель, формат вывода), и, с флажком [[ui:settings.mcp.agent.viaOllama]], переменные, которые направляют Claude Code к Ollama; переменные, которые увели бы его в облако (ключ API, Bedrock, Vertex, Foundry, свои заголовки), из его окружения убираются. Текст запроса в командную строку не попадает: промпт передаётся через стандартный ввод. Агент работает в пустой папке `agent-work` в каталоге данных приложения, поэтому файлы проекта и `QWEN.md` или `CLAUDE.md` проекта до него не доходят. Glafira запускает только Qwen Code и Claude Code; другие CLI и своя команда не поддерживаются.

## Запуски фонового ассистента {#background-runs}

Запуски идут по одному, в порядке нажатия кнопки, по всем подключениям; в очереди — до 10 запусков. Рядом с кнопкой, в консоли и в карточке запроса, строка статуса показывает запуск:

- «В очереди фонового ассистента, перед ним: 1» (или «В очереди фонового ассистента: следующий») и [[ui:llmAssist.ask.cancel]];
- «Ассистент запускается…», затем «Ассистент работает», а под ней — время, число вызовов инструментов и последний инструмент, например «1:23 · вызовов: 4 · hypothetical_index», и [[ui:llmAssist.ask.cancel]];
- «Ассистент прислал 2 предложения» — пока панель их не показала; дальше — обычное состояние отвеченного запроса;
- «Ассистент закончил без предложений» и [[ui:llmAssist.agent.summary]] (итог агента: до 5 строк, простой текст), [[ui:common.retry]], [[ui:llmAssist.agent.copyLine]], [[ui:llmAssist.ask.cancel]];
- «Ошибка фонового ассистента: …» — например, «превышен срок 15 мин», «программа не найдена: /opt/homebrew/bin/qwen», «код выхода 1», «агент не подключился к Glafira» — и [[ui:llmAssist.agent.showLog]] (если агент успел запуститься), [[ui:common.retry]], [[ui:llmAssist.agent.copyLine]], [[ui:llmAssist.ask.cancel]];
- «Запуск остановлен» (после [[ui:settings.mcp.agent.runs.stop]] в подразделе) и «Запуск прерван: Glafira закрылась» — с [[ui:common.retry]], [[ui:llmAssist.agent.copyLine]] и [[ui:llmAssist.ask.cancel]].

Предупреждение Ollama (см. [Локальная модель для фонового ассистента](llm-mcp.md#background-ollama)) показывается отдельной строкой, пока идёт запуск. Запуск без предложений или с ошибкой оставляет запрос ожидающим: его можно повторить, передать в чат ссылкой [[ui:llmAssist.agent.copyLine]] (она видна и во время запуска: чат и фон работают с одним запросом) или отменить; [[ui:llmAssist.ask.cancel]] останавливает и запуск. На один запрос — не больше пяти предложений от чата и фона вместе. Пока запрос ждёт, из той же консоли или карточки новый не создаётся: [[ui:common.retry]] берёт тот же снимок. Если запуск не удалось поставить в очередь (например, она заполнена), под кнопками написано почему, а строка статуса предлагает [[ui:llmAssist.agent.start]].

Пределы:

- [[ui:settings.mcp.agent.timeout]] — по умолчанию 15, от 2 до 60, считается от начала запуска. Когда он истекает, Glafira останавливает агента вместе с его дочерними процессами: на macOS и Linux группа процессов получает `SIGTERM`, а через 5 секунд — `SIGKILL`; на Windows агент работает в объекте задания (Job Object), который завершается целиком. Собственный предел времени Qwen Code на 30 секунд больше, поэтому первым срабатывает предел Glafira.
- 40 вызовов инструментов за запуск; дальше шлюз отвечает `run_limit`, и модель просят остановиться и написать итог. Такой запуск без предложений показывается как ошибка.
- У Claude Code без Ollama — [[ui:settings.mcp.agent.budget]]; запуск, который в него упёрся, кончается той же ошибкой.

[[ui:settings.mcp.agent.runs.title]] в подразделе — последние 20 запусков по всем подключениям: время, подключение, запрос, агент и модель, итог (предложений: N, без предложений, ошибка, отменён, прерван), длительность, вызовы и стоимость; проверки помечены словом [[ui:settings.mcp.agent.runs.check]]. Стоимость показывается только у Claude Code без Ollama: через Ollama Claude Code считает её по ценам своих моделей, и это число ничего не значит. [[ui:llmAssist.agent.summary]] показывает итог агента, [[ui:llmAssist.agent.showLog]] открывает журнал запуска (конец журнала, до 256 КБ, и кнопка [[ui:llmAssist.agent.log.reveal]]), а у текущего запуска есть [[ui:settings.mcp.agent.runs.stop]]: запуск отменяется, а запрос ждёт дальше. Выключение фонового ассистента снимает очередь, текущий запуск доводится до конца. Если Glafira закрывается во время запуска, она останавливает агента, а после следующего старта запуск помечен как прерванный; очередь не восстанавливается.

Во время запуска внизу боковой панели виден индикатор [[ui:mcp.indicator.agent]], он подсвечивается во время вызова; щелчок открывает подраздел. В [[ui:settings.mcp.sessions.title]] сессия запуска показана как «Фоновый ассистент · запрос r3a9f1c» (у проверки — «Фоновый ассистент · проверка»); [[ui:settings.mcp.sessions.disconnect]] закрывает сессию, и агент заканчивается с ошибками вызовов — чтобы остановить запуск, есть [[ui:settings.mcp.agent.runs.stop]].

Журнал запуска — `agent-runs/<id>.log` в каталоге данных приложения, доступный только вашему пользователю: командная строка агента, его вывод с метками потока и времени и код выхода, до 1 МБ на запуск, для последних 20 запусков. Модели журнал не отдаётся. Итог агента — то, что агент сообщает в конце своего вывода; у запуска, который кончился без него (срок, остановка, сбой), итога нет, а что случилось — видно в журнале. Журнал MCP записывает начало и конец каждого запуска — [[ui:settings.mcp.audit.events.agentRunStarted]] и [[ui:settings.mcp.audit.events.agentRunFinished]] со статусом, причиной, длительностью, вызовами, предложениями и стоимостью — и помечает вызовы сессии запуска его id; промпт, вывод агента и его итог туда не пишутся.

## Локальная модель для фонового ассистента {#background-ollama}

Если модель работает в Ollama на этом же компьютере, Glafira держит её тёплой: новый запуск не ждёт, пока модель загрузится, а Ollama переиспользует уже прочитанное начало запроса (системный промпт и описания инструментов), и каждый запуск платит только за снимок.

- На старте запуска Glafira спрашивает Ollama, какие модели загружены, и, если модели запуска среди них нет, загружает её в фоне, пока запускается агент (не дольше 2 минут). Ответов Ollama запуск ждёт не больше 5 секунд.
- После запуска Glafira просит Ollama держать модель в памяти столько минут, сколько задано в поле [[ui:settings.mcp.agent.keepWarm]] (по умолчанию 10, от 0 до 120). Более долгий срок, например `OLLAMA_KEEP_ALIVE=1h`, не укорачивается. При 0 Glafira в Ollama не обращается.
- [[ui:settings.mcp.agent.unload]] выгружает модель сразу. Кнопка недоступна, пока идёт запуск, и когда моделью Glafira не управляет: в поле [[ui:settings.mcp.agent.keepWarm]] — 0, Claude Code работает без Ollama или адрес не локальный.

Если на старте запуска загружена другая модель, а модели запуска в памяти нет, строка статуса и запись запуска получают предупреждение, например «Ollama может выгрузить qwen3.8:27b, чтобы загрузить qwen3.6-64k:35b-a3b». Запуск не ждёт: поместятся ли обе модели, решает Ollama. Glafira продлевает только модель запуска.

Glafira управляет моделью, только если [[ui:settings.mcp.agent.ollamaUrl]] — локальный адрес (`localhost`, `127.0.0.1` или `::1`; по умолчанию `http://127.0.0.1:11434`), а модель есть в списке Ollama и не облачная; иначе подраздел пишет, что моделью Glafira не управляет. Адрес — `http://` или `https://` с хостом и портом, без пути (не `…/v1`), и Glafira сохраняет его в таком виде. Модель запуска — та, что выбрана в подразделе; у Qwen Code при пустом поле — модель из его настроек. Claude Code без Ollama её не использует, и тогда Glafira в Ollama не обращается. Запросы к Ollama короткие, ошибка пишется только в лог приложения и на запуск не влияет. Сколько памяти занимает модель — см. [Ограничения](local-llm.md#limits) в главе «Локальные модели».

## Что видит фоновый агент {#background-scope}

Glafira запускает агента со своей MCP-конфигурацией: файл `agent-runs/<id>.mcp.json` в каталоге данных приложения (доступен только вашему пользователю, удаляется в конце запуска) запускает ту же команду `glafira-pg mcp` с билетом запуска — случайным значением, которое есть только в памяти Glafira и только пока идёт запуск. Команда передаёт билет при рукопожатии, и шлюз узнаёт сессию запуска:

- сессия подтверждена сразу, без диалога: запуск разрешили вы, когда включили фонового ассистента и нажали кнопку. Клиент агента не попадает в [[ui:settings.mcp.clients.title]], а [[ui:settings.mcp.clients.revoke]] фоновый запуск не останавливает;
- она видит только подключение и запрос своего запуска и девять инструментов: `list_connections`, `get_optimization_request`, `explain_query`, `hypothetical_index`, `get_table_details`, `get_query_details`, `get_settings`, `propose_query_rewrite` и `list_proposals`. Другое подключение, другой запрос и `propose_query_rewrite` без запроса запуска получают `not_allowed`; `run_select`, активность, топ запросов и отчёты диагностики недоступны даже на уровне [[ui:connections.form.llmLevels.data]], а сценарии (prompts) не предлагаются. Сессия проверки не видит ни одного подключения;
- уровень доступа подключения действует как обычно: на уровне [[ui:connections.form.llmLevels.diagnostics]] литералы в ответах инструментов маскируются, а снимок запроса — нет (см. [Запрос на оптимизацию и предложения](llm-mcp.md#optimization));
- политика и выключатель [[ui:settings.mcp.enable]] действуют, как на любую сессию.

Билет сам по себе ничего не открывает: без токена из `mcp.json` и доступа к сокету, которые есть только у вашего пользователя, подключиться нельзя. Он лишь отличает сессию, которую запустила Glafira, от любой другой сессии того же клиента. Если агент во время запуска перезапустит MCP-сервер, новая сессия сменит прежнюю; в конце запуска его сессии закрываются.

Встроенные инструменты агента — оболочку, файлы, веб, субагентов — пресет выключает, и у модели остаются только инструменты Glafira своего запуска. Перед первым ходом модели Glafira ещё и проверяет список инструментов, который агент сообщает в начале своего вывода: если в нём есть что-то кроме инструментов Glafira (новая версия CLI может принести встроенный инструмент, которого пресет ещё не знает), списка нет или модель начала работу раньше, чем агент его сообщил, запуск сразу останавливается. Тексты из базы (тексты запросов, комментарии, имена) для модели — данные, и инструкции Glafira для сессии об этом говорят. Худший исход «инструкции», подложенной в базу, — бесполезное предложение или потраченные минуты и деньги в пределах срока, 40 вызовов и предела расходов: предложение ничего не меняет, пока вы не примените его сами.

Ваши собственные настройки агента пресет в фоновый запуск тоже не пускает: Qwen Code запускается с `--safe-mode`, который выключает ваши хуки, расширения и навыки, а Claude Code читает только настройки проекта и локальные (`--setting-sources project,local`), поэтому ваши хуки, плагины и разрешения не действуют; рабочая папка пустая, так что и настроек проекта нет. Читает ли фоновый запуск `~/.qwen/QWEN.md` или `~/.claude/CLAUDE.md`, проверка CLI не показала: не держите в них того, что не должно читаться без вас.

Снимок и ответы инструментов уходят провайдеру модели агента, как в чате, но рядом нет человека: об этом — постоянная пометка в подразделе. У облачной модели каждый запуск — платный вызов: задайте предел расходов Claude Code и проверьте цены своего провайдера Qwen Code. Администратор может запретить фонового ассистента ключом политики `mcpAgentEnabled` (см. [Политика организации](llm-mcp.md#policy)).

## Примеры вопросов {#examples}

- «Что происходит на кластере billing?» — ассистент начнёт со сводки здоровья и откроет отчёты по находкам.
- «Кто держит горизонт xmin на billing и что с этим делать?»
- «Почему растёт лаг pg-3?»
- «Что грузит базу последние 15 минут?» — окно за 15 минут есть, если вкладка [[ui:diag.tools.queries]] была открыта; иначе ассистент понаблюдает за топом до 50 секунд или возьмёт статистику с момента сброса.
- «Покажи план самого тяжёлого запроса из топа и проверь, поможет ли индекс по status» — план без выполнения и гипотеза через hypopg.
- «Оптимизируй запрос из Glafira» после кнопки [[ui:llmAssist.ask.button]] (или строка с id из буфера обмена) — ассистент забирает запрос, а его предложения появляются в панели [[ui:llmAssist.panel.title]].
- «Сколько заказов в каждом статусе на тестовом стенде?» — на уровне [[ui:connections.form.llmLevels.data]] ассистент прочитает ответ инструментом `run_select`.

## Если не работает {#troubleshooting}

Клиент показывает сообщение из Glafira:

- `MCP is disabled in Glafira` — отметьте [[ui:settings.mcp.enable]] и перезапустите MCP-сервер в клиенте;
- `MCP is disabled by your organization` — MCP запрещён политикой организации;
- `Glafira did not start the MCP server within 25 s` — откройте Glafira сами, проверьте статус в разделе [[ui:settings.mcp.section]] и перезапустите сервер в клиенте;
- `bad_token` — перезапустите MCP-сервер в клиенте: Glafira выдаёт новый токен при каждом запуске сервера.

Ошибки фонового ассистента видны в строке статуса и в [[ui:settings.mcp.agent.runs.title]]; [[ui:llmAssist.agent.showLog]] открывает журнал запуска с сообщениями самого агента:

- «программа не найдена» (`cliNotFound`) — путь в подразделе неверен или CLI переустановлен в другое место: нажмите [[ui:settings.mcp.agent.find]] или поправьте путь, затем [[ui:common.retry]];
- «агент не подключился к Glafira» (`notConnected`) — агент закончился, не вызвав ни одного инструмента Glafira. Почему — обычно видно в журнале: ошибка входа или провайдера, несуществующая модель, версия CLI, которая не знает флага пресета. [[ui:settings.mcp.agent.check]] проверяет всю настройку;
- «превышен срок …» (`timeout`) — модель не успевает за [[ui:settings.mcp.agent.timeout]]: увеличьте срок, выберите модель быстрее (для локальной — MoE с малым числом активных параметров) или держите модель тёплой между запусками (см. [Локальная модель для фонового ассистента](llm-mcp.md#background-ollama));
- «агенту доступны не только инструменты Glafira: …; запуск остановлен до первого хода» (`unsafeTools`) — в новой версии CLI есть встроенный инструмент, который пресет вашей версии Glafira не выключает: обновите Glafira или возьмите версию CLI, на которой она проверена (Qwen Code 0.26.5, Claude Code 2.1.319). «Агент не сообщил список своих инструментов; запуск остановлен» — CLI не начал вывод со списка своих инструментов (например, старая версия): что он напечатал, видно в журнале;
- `bad_ticket` в журнале («The background run is over: start it again in Glafira») — агент перезапустил MCP-сервер, когда запуск уже кончился или был остановлен: нажмите [[ui:common.retry]].

Известные ограничения: на Linux без `XDG_RUNTIME_DIR` и при длинном пути каталога данных сокет создаётся в общем `/tmp` с фиксированным именем `glafira-pg-mcp.sock` (права 0600); ошибка сервера в ответе по `queryId` из `pg_stat_statements` может содержать значения данных; ранее созданная пользовательская функция, ошибочно помеченная `IMMUTABLE`, может вычисляться при построении плана, и её результат попадёт в подробный план (изменить данные при этом нельзя: транзакция только для чтения); константы, которые планировщик вычисляет заранее (например, `repeat('x', 100000000)`), попадают в план целиком, поэтому план больше 8 МБ Glafira не разбирает и отвечает ошибкой с советом уменьшить такие значения (ассистенту — `invalid_sql`); в базе с кодировкой `SQL_ASCII` обрезка длинного значения может разрезать символ, и тогда ответ — `invalid_sql` с советом убрать колонку или выбрать её через `encode(…, 'hex')`; полное время вызова `run_select` может превышать 10 секунд (к времени запроса добавляются подключение, пробный план и чтение).

Ошибки вызовов ассистент видит сам и обычно объясняет: `client_not_approved` — ответьте на диалог в Glafira; `not_allowed` — подключение закрыто для ассистента (уровень [[ui:connections.form.llmLevels.off]]) или его нет, а в фоновом запуске — ещё и инструмент, подключение или запрос вне запуска; `run_limit` — фоновый запуск сделал 40 вызовов и должен закончить; `rate_limited` и `busy` — сработал предел (60 вызовов в минуту, одно наблюдение за раз на сессию), ассистент повторит позже; `data_not_allowed` — инструменту `run_select` нужен уровень [[ui:connections.form.llmLevels.data]], а у подключения [[ui:connections.form.llmLevels.diagnostics]]; `data_disabled` — чтение данных ограничено политикой организации; `forbidden_function`, `user_function` и `invalid_sql` — Glafira отвергла SQL ассистента, причина — в сообщении, ассистент перепишет запрос; `request_closed` — вы отменили запрос на оптимизацию; `TIMEOUT` у `run_select` — запрос не вернул ни одной строки за 10 секунд.
